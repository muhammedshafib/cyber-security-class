# 1. Understand Linux Fundamentals

Linux Fundamentals means understanding **how a Linux operating system is organized, how files are stored, how users are managed, how programs run, and how background services work**.

The five important areas are:

1. **Linux ecosystem**
2. **File system hierarchy**
3. **Users and groups**
4. **Processes**
5. **System services**

---

# A. Linux Ecosystem

## What is Linux?

Linux is an **open-source operating system kernel**.

Technically:

> **Linux = Kernel**

The complete operating system is usually called a **Linux distribution (distro)**, which combines the Linux kernel with system utilities, libraries, package managers, desktop environments, and applications.

### Simple example

Think of a computer as a car:

* **Linux kernel** → engine
* **Shell** → steering/control interface
* **GNU utilities** → tools
* **Package manager** → store/mechanic for installing software
* **Desktop environment** → dashboard
* **Applications** → things you use

---

## Linux Architecture

```text
                 USER
                  │
        Applications / Programs
                  │
              Shell / GUI
                  │
        System Libraries
                  │
            Linux Kernel
                  │
              Hardware
```

### Kernel

The kernel is the core of Linux.

It manages:

* CPU
* RAM
* Processes
* Storage
* Networking
* Devices
* Security
* System calls

Check kernel information:

```bash
uname -a
```

More detailed:

```bash
uname -r
```

Example:

```text
6.8.0-xx-generic
```

## What is a Linux Distribution?

A distribution packages the Linux kernel with other software.

Popular distributions include:

* Ubuntu
* Debian
* Fedora
* Arch Linux
* Linux Mint
* Kali Linux
* Rocky Linux
* AlmaLinux
* openSUSE

### Ubuntu vs Kali Linux

**Ubuntu** is designed as a general-purpose distribution.

**Kali Linux** is specialized for cybersecurity and penetration-testing activities.

Kali contains many security tools, but it is still fundamentally a Linux distribution.

# B. File System Hierarchy

Linux organizes files in a **tree structure**.

Unlike Windows, Linux doesn't normally use drives such as:

```text
C:\
D:\
```

Instead, Linux starts from:

```text
/
```

This is called the **root directory**.

### Basic structure

```text
/
├── bin
├── boot
├── dev
├── etc
├── home
├── lib
├── media
├── mnt
├── opt
├── proc
├── root
├── run
├── sbin
├── srv
├── sys
├── tmp
├── usr
└── var
```

---

# C. Users and Groups

Linux is a **multi-user operating system**.

Multiple users can exist on the same system, and each user can have different permissions.

For example:

```text
root
alice
bob
shafi
```

---

## Root User

The root account is the Linux superuser.

Root has extensive privileges over the system.

Root's UID is:

```text
0
```

Check current user:

```bash
whoami
```

---

## User ID — UID

Every Linux user has a numerical **UID**.

Check:

```bash
id
```

Example:

```text
uid=1000(shafi) gid=1000(shafi) groups=1000(shafi)
```

---

## Group ID — GID

A group also has a numerical ID.

Check:

```bash
id
```

---

## Important user commands

### `whoami`

Shows current user.


### `id`

Shows UID, GID, and groups.

```bash

```

### `who`

Shows logged-in users.

```bash

```

### `w`


# Linux Permissions

Linux permissions are extremely important for cybersecurity.

Example:

```text
-rwxr-xr--
```

Three main permission categories:

```text
Owner
Group
Others
```

Three main permissions:

```text
r = read
w = write
x = execute
```

Example:

```text
-rwxr-xr--
```

Breakdown:

```text
Owner  → rwx
Group  → r-x
Others → r--
```

Numerical permissions:

```text
r = 4
w = 2
x = 1
```

Therefore:

```text
rwx = 7
r-x = 5
r-- = 4
```

So:

```text
755
```

means:

```text
Owner  = rwx = 7
Group  = r-x = 5
Others = r-x = 5
```

Change permissions:

```bash
chmod 755 file
```

Change owner:

```bash
sudo chown username file
```

# D. Processes

A **process** is a running instance of a program.

For example, when you execute:

```bash
firefox
```

the operating system creates a process for Firefox.

Another example:

```bash
python script.py
```

creates a Python process.

---

## Process ID — PID

Every process receives a unique **Process ID (PID)**.

View processes:

```bash
ps
```

More detailed:

```bash
ps aux
```

Dynamic process monitoring:

```bash
top
```

If installed:

```bash
htop
```

---

## Important Process Commands

### `ps`

Shows processes.

```bash
ps
```

### `ps aux`

Shows processes from all users with detailed information.

```bash
ps aux
```

### `top`

Live process monitoring:

```bash
top
```

### `htop`

Interactive process viewer:

```bash
htop
```

### `pgrep`

Find a process by name:

```bash
pgrep firefox
```

### `kill`

Send a signal to a process:

```bash
kill PID
```

Example:

```bash
kill 1234
```

Force termination:

```bash
kill -9 1234
```

Use `-9` carefully because it does not allow the process to perform normal cleanup.

### `pkill`

Terminate processes based on a name/pattern:

```bash
pkill processname
```

---

# Foreground and Background Processes

A command normally runs in the foreground:

```bash
ping 8.8.8.8
```

You can stop/suspend it with:

```text
Ctrl + C
```

Run a command in the background:

```bash
command &
```

Example:

```bash
sleep 100 &
```

See jobs:

```bash
jobs
```

---

# Process States

Processes can have different states.

Common states include:

```text
R = Running
S = Sleeping
D = Uninterruptible sleep
T = Stopped
Z = Zombie
```

You can see process state with:

```bash
ps aux
```

---

## Parent and Child Processes

Processes can create other processes.

Example:

```text
Terminal
   │
   └── Bash
        │
        └── Python
```

A process has:

* PID
* Parent PID (PPID)

View this with:

```bash
ps -ef
```

# E. System Services

A **service** is a program that runs in the background to provide a function to the system or other applications.

Examples:

* SSH server
* Web server
* DNS service
* Database server
* Network service

Modern Linux distributions commonly use **systemd** as the system and service manager.

---

# What is systemd?

`systemd` is a system and service manager.

It is responsible for tasks such as:

* Starting services during boot
* Managing services
* Managing dependencies
* Tracking processes
* Managing certain system resources
* Handling system targets

The main command used to interact with systemd services is:

```bash
systemctl
```

---

# Check a Service

Example:

```bash
systemctl status ssh
```

Depending on the distribution, the service may be named `sshd` instead.

---

## Start a Service

```bash
sudo systemctl start ssh
```

---

## Stop a Service

```bash
sudo systemctl stop ssh
```

---

## Restart a Service

```bash
sudo systemctl restart ssh
```

---

## Enable a Service at Boot

```bash
sudo systemctl enable ssh
```

This means the service is configured to start automatically during boot.

---

## Disable a Service at Boot

```bash
sudo systemctl disable ssh
```

---

## Check Whether a Service Is Running

```bash
systemctl is-active ssh
```

---

## Check Whether a Service Starts at Boot

```bash
systemctl is-enabled ssh
```

---

## List Running Services

```bash
systemctl --type=service --state=running
```

List all service units:

```bash
systemctl list-units --type=service
```

# How These Five Topics Connect

This is very important for an exam or interview.

```text
                  LINUX
                    │
       ┌────────────┼────────────┐
       ↓            ↓            ↓
 Filesystem      Users       Processes
       │            │            │
       │       Permissions       │
       │            │            │
       └────────────┼────────────┘
                    ↓
              System Services
                    │
                 systemd
                    │
                    ↓
              Running System
```

### Real-world example: SSH

Suppose you have an Ubuntu server running SSH.

**1. File system**

SSH configuration can be found under:

```text
/etc/ssh/
```

**2. User**

A user connects using an account:

```text
shafi
```

**3. Permissions**

The user needs appropriate permissions to access files.

**4. Process**

The SSH server runs as one or more processes.

Check:

```bash
ps aux | grep ssh
```

**5. Service**

SSH is managed as a system service:

```bash
systemctl status ssh
```

This single example connects **filesystem + users + permissions + processes + services**.

# Exam-Oriented Questions

### 1. What is Linux?

**Answer:**
Linux is an open-source operating-system kernel. Linux distributions combine the kernel with system utilities, libraries, package managers, and applications to provide a complete operating system.

### 2. What is the Linux root directory?

**Answer:**
`/` is the top-level directory of the Linux filesystem. All other directories and files exist under this hierarchy.

### 3. What is `/etc`?

**Answer:**
`/etc` contains system-wide configuration files.

### 4. What is `/home`?

**Answer:**
`/home` contains the personal directories of normal users.

### 5. What is a UID?

**Answer:**
UID stands for **User ID**. It is a numerical identifier assigned to a Linux user.

### 6. What is a process?

**Answer:**
A process is a running instance of a program.

### 7. What is PID?

**Answer:**
PID stands for **Process ID**, a unique number assigned to a running process.

### 8. What is systemd?

**Answer:**
systemd is a system and service manager commonly used by modern Linux distributions. It manages system startup and services.

### 9. What is `systemctl`?

**Answer:**
`systemctl` is the command-line utility used to control and inspect systemd-managed services and other units.

### 10. Difference between a process and a service?

**Answer:**

**Process:** A running instance of a program.

**Service:** A background program/function managed by the operating system, commonly through a service manager such as systemd.
