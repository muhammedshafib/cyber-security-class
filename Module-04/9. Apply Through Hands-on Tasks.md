# 9. Apply Through Hands-on Tasks

This section focuses on **practical Linux and cybersecurity tasks**. The goal is to take the commands and concepts learned earlier and use them in real Linux lab exercises.

> **Practice these tasks only on your own Linux machine or an authorized lab/VM.**

---

## a. Administer Linux Systems

Linux administration means managing **users, files, permissions, processes, services, storage, and network settings**.

### 1. Check the current user

```bash
whoami
```

```bash
id
```

These commands show your username, UID, groups, and privileges.

---

### 2. Create a user

```bash
sudo useradd -m securityuser
```

Set a password:

```bash
sudo passwd securityuser
```

Check the user:

```bash
id securityuser
```

---

### 3. Create a group

```bash
sudo groupadd security
```

Add the user to the group:

```bash
sudo usermod -aG security securityuser
```

Verify:

```bash
groups securityuser
```

---

### 4. Manage file permissions

Create a test file:

```bash
touch security.txt
```

Change permissions:

```bash
chmod 600 security.txt
```

Check:

```bash
ls -l security.txt
```

`600` means:

```text
Owner  → read + write
Group  → no permission
Others → no permission
```

---

### 5. Manage ownership

```bash
sudo chown securityuser:security security.txt
```

Verify:

```bash
ls -l security.txt
```

---

### 6. Manage services

Check a service:

```bash
systemctl status ssh
```

Start:

```bash
sudo systemctl start ssh
```

Stop:

```bash
sudo systemctl stop ssh
```

Restart:

```bash
sudo systemctl restart ssh
```

---

### 7. Monitor processes

```bash
ps aux
```

Search for a specific process:

```bash
ps aux | grep firefox
```

You can also use:

```bash
top
```

---

### 8. Check disk usage

```bash
df -h
```

Check the size of a directory:

```bash
du -sh /home
```

---

# b. Analyze Security Logs

Security logs provide information about **authentication, services, errors, and system activity**.

Common locations include:

```text
/var/log/
/var/log/auth.log
/var/log/syslog
```

On systems using systemd, `journalctl` is also important.

---

## 1. View authentication logs

On Debian/Ubuntu/Kali systems, for example:

```bash
sudo cat /var/log/auth.log
```

Search for failed authentication:

```bash
sudo grep -i "failed" /var/log/auth.log
```

Search for successful authentication:

```bash
sudo grep -i "accepted" /var/log/auth.log
```

---

## 2. Count failed attempts

```bash
sudo grep -i "failed" /var/log/auth.log | wc -l
```

This counts matching lines.

---

## 3. Find failed SSH attempts

```bash
sudo grep "Failed password" /var/log/auth.log
```

You can investigate:

* Username
* Source IP
* Date/time
* Number of attempts

---

## 4. Use `journalctl`

View system logs:

```bash
sudo journalctl
```

Show errors:

```bash
sudo journalctl -p err
```

View SSH service logs:

```bash
sudo journalctl -u ssh
```

View recent logs:

```bash
sudo journalctl --since "1 hour ago"
```

---

## 5. Live log monitoring

```bash
sudo tail -f /var/log/auth.log
```

Now you can observe new authentication events as they are written.

Press:

```text
Ctrl + C
```

to stop.

# c. Build Shell Scripts

A **shell script** is a file containing Linux commands that can be executed automatically.

Create a file:

```bash
nano system-info.sh
```

Add:

```bash
#!/bin/bash

echo "===== System Information ====="

echo "User:"
whoami

echo "Hostname:"
hostname

echo "IP Address:"
hostname -I

echo "Disk Usage:"
df -h

echo "Memory:"
free -h

echo "Uptime:"
uptime
```

Save the file.

Give execute permission:

```bash
chmod +x system-info.sh
```

Run it:

```bash
./system-info.sh
```

### What this script does

```text
whoami
   ↓
Current user

hostname
   ↓
Computer name

hostname -I
   ↓
IP address

df -h
   ↓
Disk usage

free -h
   ↓
Memory usage

uptime
   ↓
System uptime
```

# d. Automate Administrative Tasks

Automation means allowing a script to perform repetitive tasks automatically.

For example, create:

```bash
nano admin-check.sh
```

Script:

```bash
#!/bin/bash

echo "===== Linux Administration Report ====="

echo
echo "Current User:"
whoami

echo
echo "System:"
hostname

echo
echo "Uptime:"
uptime

echo
echo "Disk Usage:"
df -h

echo
echo "Memory Usage:"
free -h

echo
echo "Running Processes:"
ps aux | head -10

echo
echo "Listening Ports:"
ss -tuln
```

Make executable:

```bash
chmod +x admin-check.sh
```

Run:

```bash
./admin-check.sh
```

Now several administrative checks are performed with **one command**.

---

# Automating with `cron`

Linux can automatically execute scripts at scheduled times using **cron**.

Edit your user's cron jobs:

```bash
crontab -e
```

Example:

```text
0 * * * * /home/user/admin-check.sh
```

This runs the script **once every hour**.

Another example:

```text
0 9 * * * /home/user/admin-check.sh
```

This runs every day at **9:00 AM**.

⚠️ Use the correct absolute path and test the script manually before scheduling it.

# e. Create Security Monitoring Scripts

A security monitoring script can automatically check important security indicators.

For example, create:

```bash
nano security-monitor.sh
```

Use:

```bash
#!/bin/bash

echo "================================"
echo "     SECURITY MONITORING"
echo "================================"

echo
echo "[1] Current User"
whoami

echo
echo "[2] Failed Authentication Attempts"
if [ -f /var/log/auth.log ]; then
    grep -i "failed" /var/log/auth.log | tail -10
else
    echo "auth.log not found; check journalctl instead."
fi

echo
echo "[3] Listening Ports"
ss -tuln

echo
echo "[4] Disk Usage"
df -h

echo
echo "[5] Running Processes"
ps aux --sort=-%cpu | head -10

echo
echo "[6] Recent System Errors"
journalctl -p err -n 10 --no-pager

echo
echo "===== Monitoring Complete ====="
```

Make it executable:

```bash
chmod +x security-monitor.sh
```

Run:

```bash
sudo ./security-monitor.sh
```

---

# 🔍 What the Security Monitoring Script Checks

### 1. User

```bash
whoami
```

Identifies the account running the script.

### 2. Authentication

```bash
grep -i "failed" /var/log/auth.log
```

Looks for failed authentication events where that log exists.

### 3. Network

```bash
ss -tuln
```

Shows listening TCP/UDP ports.

### 4. Storage

```bash
df -h
```

Shows disk utilization.

### 5. Processes

```bash
ps aux --sort=-%cpu
```

Helps identify processes consuming significant CPU.

### 6. System errors

```bash
journalctl -p err
```

Displays journal entries at error priority.

# 🧪 Hands-on Mini Project

You can combine everything you've learned into one project:

## **Linux Security Monitoring System**

### Step 1 — Create the project

```bash
mkdir ~/security-monitor
cd ~/security-monitor
```

### Step 2 — Create the script

```bash
nano monitor.sh
```

### Step 3 — Add monitoring commands

```bash
#!/bin/bash

REPORT="$HOME/security-monitor/security-report.txt"

echo "===== Security Report =====" > "$REPORT"

echo "Date:" >> "$REPORT"
date >> "$REPORT"

echo >> "$REPORT"
echo "Current User:" >> "$REPORT"
whoami >> "$REPORT"

echo >> "$REPORT"
echo "Disk Usage:" >> "$REPORT"
df -h >> "$REPORT"

echo >> "$REPORT"
echo "Listening Ports:" >> "$REPORT"
ss -tuln >> "$REPORT"

echo >> "$REPORT"
echo "Recent Processes:" >> "$REPORT"
ps aux | head -10 >> "$REPORT"

echo >> "$REPORT"
echo "Recent Errors:" >> "$REPORT"
journalctl -p err -n 10 --no-pager >> "$REPORT"

echo
echo "Security report created:"
echo "$REPORT"
```

### Step 4 — Give permission

```bash
chmod +x monitor.sh
```

### Step 5 — Execute

```bash
./monitor.sh
```

### Step 6 — Read the report

```bash
cat security-report.txt
```

Or:

```bash
less security-report.txt
```
