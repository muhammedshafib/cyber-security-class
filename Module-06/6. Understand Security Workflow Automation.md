# 6. Understand Security Workflow Automation

**Security workflow automation** means using Python to automatically move a security task through different steps instead of doing everything manually.

### Simple example

```text
Security Event
      ↓
Create Ticket
      ↓
Create Incident
      ↓
Send Notification
      ↓
Generate Report
      ↓
Complete Workflow
```

This is commonly used in **SOC (Security Operations Center)** environments.

---

# 6.1 Ticket Creation Concepts

## What is a ticket?

A **ticket** is a record of a problem or security event that needs investigation.

For example:

```text
Ticket ID: 1001
Title: Multiple failed logins
IP: 192.168.1.10
Severity: High
Status: Open
```

Instead of manually creating this information, Python can create a simple ticket automatically.

---

## Simple Ticket

```python
ticket = {
    "id": 1001,
    "title": "Multiple failed logins",
    "ip": "192.168.1.10",
    "severity": "High",
    "status": "Open"
}

print("Ticket ID:", ticket["id"])
print("Title:", ticket["title"])
print("IP:", ticket["ip"])
print("Severity:", ticket["severity"])
print("Status:", ticket["status"])
```

### Output

```text
Ticket ID: 1001
Title: Multiple failed logins
IP: 192.168.1.10
Severity: High
Status: Open
```

Here we're using a **dictionary** to represent a ticket.

---

## Why tickets are useful

Without tickets:

```text
Alert
 ↓
Analyst remembers it
 ↓
Investigates
 ↓
Maybe forgets documentation
```

With tickets:

```text
Alert
 ↓
Ticket
 ↓
Investigation
 ↓
Evidence
 ↓
Resolution
 ↓
Documentation
```

A ticket provides a record of what happened.

# 6.2 Incident Workflow Automation

## What is an incident?

An **incident** is a security event or group of events that requires investigation or response.

For learning, imagine:

```text
5 failed logins
      ↓
Potential security incident
```

A workflow can automatically process it.

```text
Event detected
      ↓
Check severity
      ↓
Create incident
      ↓
Notify analyst
      ↓
Generate report
```

---

## Simple Incident Code

```python
event = "failed_login"
count = 5

if event == "failed_login" and count >= 5:

    incident = {
        "type": "Multiple failed logins",
        "count": count,
        "severity": "High",
        "status": "Open"
    }

    print("Incident created")
    print(incident)
```

Output:

```text
Incident created
{'type': 'Multiple failed logins', 'count': 5, 'severity': 'High', 'status': 'Open'}
```

---

# Understanding the Code

### Event

```python
event = "failed_login"
```

Stores the event type.

### Count

```python
count = 5
```

Stores how many times the event occurred.

### Condition

```python
if event == "failed_login" and count >= 5:
```

Checks two things:

```text
Is it a failed login?
        AND
Are there at least 5?
```

If both are true, an incident is created.

# 6.3 Notification Systems

## What is a notification?

A notification informs someone that an event requires attention.

Examples:

```text
Console message
Email
Chat message
SMS
SOC dashboard
```

For beginner Python, start with a simple console notification.

```python
print("ALERT: Security incident detected!")
```

---

## Notification Function

We can make it reusable:

```python
def send_notification(message):

    print("NOTIFICATION")
    print(message)


send_notification("Multiple failed logins detected")
```

Output:

```text
NOTIFICATION
Multiple failed logins detected
```

---

# 6.4 Report Generation

## What is a security report?

A report summarizes what the automation system found.

For example:

```text
SECURITY REPORT
----------------
Event: Multiple failed logins
IP: 192.168.1.10
Attempts: 5
Severity: High
Status: Open
```

Python:

```python
incident = {
    "event": "Multiple failed logins",
    "ip": "192.168.1.10",
    "attempts": 5,
    "severity": "High",
    "status": "Open"
}

print("SECURITY REPORT")
print("----------------")

print("Event:", incident["event"])
print("IP:", incident["ip"])
print("Attempts:", incident["attempts"])
print("Severity:", incident["severity"])
print("Status:", incident["status"])
```

---

# Saving the Report to a File

Instead of only displaying the report, we can save it.

```python
incident = {
    "event": "Multiple failed logins",
    "ip": "192.168.1.10",
    "attempts": 5,
    "severity": "High",
    "status": "Open"
}

with open("security_report.txt", "w") as file:

    file.write("SECURITY REPORT\n")
    file.write("----------------\n")

    file.write("Event: " + incident["event"] + "\n")
    file.write("IP: " + incident["ip"] + "\n")
    file.write("Attempts: " + str(incident["attempts"]) + "\n")
    file.write("Severity: " + incident["severity"] + "\n")
    file.write("Status: " + incident["status"] + "\n")

print("Report created")
```

Now Python creates:

```text
security_report.txt
```

# 6.5 Process Orchestration

This is the most important concept in this section.

## What is orchestration?

**Orchestration means coordinating multiple automated tasks in the correct order.**

For example:

```text
1. Detect event
       ↓
2. Analyze event
       ↓
3. Create ticket
       ↓
4. Send notification
       ↓
5. Generate report
```

Instead of having five independent scripts, one workflow controls them.

---

# Simple Orchestration

```python
def detect_event():

    return {
        "type": "failed_login",
        "ip": "192.168.1.10",
        "count": 5
    }


def create_ticket(event):

    print("Ticket created")


def send_notification(event):

    print("Notification sent")


def generate_report(event):

    print("Report generated")


event = detect_event()

create_ticket(event)

send_notification(event)

generate_report(event)
```

Output:

```text
Ticket created
Notification sent
Report generated
```

This is basic **process orchestration**.

---

# Understanding the Flow

```python
event = detect_event()
```

First, detect something.

Then:

```python
create_ticket(event)
```

Create a ticket.

Then:

```python
send_notification(event)
```

Notify someone.

Finally:

```python
generate_report(event)
```

Create documentation.

So:

```text
Detect
  ↓
Ticket
  ↓
Notification
  ↓
Report
```

# 6.6 Add Decision Making

Real workflows often need conditions.

```python
event = {
    "type": "failed_login",
    "count": 5
}

if event["count"] >= 5:

    print("High-priority incident")

    print("Create ticket")
    print("Send notification")
    print("Generate report")

else:

    print("Low-priority event")
```

The workflow now depends on the event.

def detect_event():

# 6.10 Practical Project

Let's build a simple **Security Incident Workflow Automation** project.

Create:

```text
security_workflow.py
```

Code:

```python
def detect_event():

    return {
        "type": "failed_login",
        "ip": "192.168.1.10",
        "count": 6
    }


def create_ticket(event):

    ticket = {
        "title": "Multiple failed logins",
        "ip": event["ip"],
        "attempts": event["count"],
        "status": "Open"
    }

    print("Ticket created")

    return ticket


def send_notification(ticket):

    print("ALERT!")
    print("IP:", ticket["ip"])
    print("Attempts:", ticket["attempts"])


def generate_report(ticket):

    with open("incident_report.txt", "w") as file:

        file.write("SECURITY INCIDENT REPORT\n")
        file.write("-------------------------\n")

        file.write("Title: " + ticket["title"] + "\n")
        file.write("IP: " + ticket["ip"] + "\n")
        file.write("Attempts: " + str(ticket["attempts"]) + "\n")
        file.write("Status: " + ticket["status"] + "\n")

    print("Report generated")


event = detect_event()


if event["count"] >= 5:

    ticket = create_ticket(event)

    send_notification(ticket)

    generate_report(ticket)

else:

    print("No incident")
```

Run:

```text
python security_workflow.py
```

You should see:

```text
Ticket created
ALERT!
IP: 192.168.1.10
Attempts: 6
Report generated
```

And Python creates:

```text
incident_report.txt
```

# 🧠 What You Must Remember

| Topic                     | Simple meaning                           |
| ------------------------- | ---------------------------------------- |
| **Ticket creation**       | Create a record for an event/problem     |
| **Incident workflow**     | Steps used to handle a security event    |
| **Notification**          | Inform an analyst/team                   |
| **Report generation**     | Save investigation information           |
| **Process orchestration** | Connect multiple tasks into one workflow |

### Easy formula:

**Detect → Analyze → Ticket → Notify → Report**

The main goal of security workflow automation is **not simply to automate everything**. It is to automate repetitive steps while keeping appropriate **human review and authorization** for important security decisions.
