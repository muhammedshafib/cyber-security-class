# 8. AI-Assisted Automation

AI can help us **design, write, explain, and improve automation scripts**. But we should **not blindly trust AI-generated code**. We must review and test it.

## 1. Use AI For

### 1.1 Script Generation

AI can help create a Python script based on a requirement.

**Example requirement:**

> “Create a Python script that counts failed logins in a log file.”

AI may generate:

```python
failed = 0

with open("security.log", "r") as file:
    for line in file:
        if "FAILED" in line:
            failed = failed + 1

print("Failed logins:", failed)
```

**Benefit:**

* Saves development time
* Gives a starting point
* Helps beginners learn code

**Important:** Understand the code before using it.

---

### 1.2 Log Parsing Ideas

AI can suggest ways to extract useful information from logs.

For example, a log may contain:

```text
Failed login alice 192.168.1.10
Failed login bob 192.168.1.20
Successful login john 192.168.1.30
```

AI can suggest:

```text
Log file
   ↓
Find "Failed login"
   ↓
Extract username
   ↓
Extract IP address
   ↓
Count failures
   ↓
Generate alert
```

AI can help identify:

* Important events
* IP addresses
* Usernames
* Error messages
* Repeated activities
* Possible patterns

---

### 1.3 Workflow Design

AI can help design an automation workflow.

**Example: Failed-login monitoring**

```text

Find Failed Login

Extract IP
   ↓

   ↓
```

This helps us plan the program **before writing code**.

For example, AI may suggest:

# 2. Validate Outputs

This is the **most important part** of AI-assisted automation.

AI-generated code can contain:

* Logic mistakes
* Incorrect assumptions
* Security vulnerabilities
* Missing error handling
* Incorrect commands

So always **review → test → verify**.

---

## 2.1 Review Automation Logic

Check whether the program actually does what you want.

Example:

```python
count = 3

if count >= 5:
    print("ALERT")
```

Ask:

> Should an alert happen at 3 attempts?

No.

The condition says:

```python
count >= 5
```

So the alert only happens when the count is **5 or more**.

---

## 2.2 Verify Workflow Behavior

Test different situations.

For a failed-login detector:

| Test             | Expected result      |
| ---------------- | -------------------- |
| 1 failed login   | No alert             |
| 3 failed logins  | No alert             |
| 5 failed logins  | Alert                |
| 10 failed logins | Alert                |
| Empty log        | No crash             |
| Missing log file | Proper error message |

This helps confirm that the automation works correctly.

### Simple testing idea

```text
Normal Input
     ↓
Test
     ↓
Boundary Input
     ↓
Test
     ↓
Invalid Input
     ↓
Test
     ↓
Check Results
```

---

# 2.3 Assess Security Implications

Before using AI-generated security automation, ask:

### 🔐 1. Is user input handled safely?

Avoid unsafe command execution such as:

```python
subprocess.run(user_input, shell=True)
```

Untrusted input can create command-injection risks.

---

### 🔐 2. Are passwords or API keys exposed?

Never put secrets directly into code:

```python
password = "MyPassword123"
```

Use safer secret-management methods instead.

---

### 🔐 3. Does the script have unnecessary permissions?

A script should have only the permissions it actually needs.

---

### 🔐 4. Does the automation make dangerous decisions automatically?

For example, don't automatically delete files or disable accounts just because a simple rule triggered.

A safer beginner workflow is:

```text
Detect
  ↓
Alert
  ↓
Human Review
  ↓
Decision
  ↓
Action
```

```text
             ↓
      Check Security
             ↓
          Test
             ↓

             ↓
      Improve Script
             ↓

```

## ⭐ Easy Formula to Remember

**AI → Generate → Review → Test → Verify → Secure → Use**

### Practical example

You want to create a **security log monitoring script**.

You can ask AI:

> “Create a simple Python script that reads a security log, counts failed logins by IP address, generates an alert when an IP has 5 or more failures, and explain every line.”

Then:

1. **Generate** the code with AI.
2. **Understand** every part.
3. **Review** the logic.
4. **Test** with different logs.
5. **Check** for security problems.
6. **Improve** the script.
7. **Use** it only in an authorized environment.

**Key idea:** AI is an assistant for automation—not a replacement for testing, security review, and human judgment.
