# 4. Understand Asymmetric Encryption

**Asymmetric encryption** is a type of cryptography that uses **two related keys**:

* 🔓 **Public key** — can be shared
* 🔐 **Private key** — must be kept secret

This is different from symmetric encryption, where the same secret key is used on both sides.

### Basic idea

```text
        ASYMMETRIC CRYPTOGRAPHY

       🔓 Public Key
            │
            ↓
       Encryption
            │
            ↓
       🔒 Ciphertext
            │
            ↓
       Decryption
            │
            🔐
       Private Key
```

---

# 1. Public Keys

A **public key** is a cryptographic key that can be shared with other people or systems.

For example:

```text
Alice
  │
  └── 🔓 Alice's Public Key
          ↓
      Can be shared
```

You don't normally need to keep a public key secret.

### Example

Imagine Alice wants Bob to send her an encrypted message.

Alice gives Bob her:

```text
🔓 Public Key
```

Bob can use that public key to encrypt information intended for Alice.

```text
Bob
 │
 │ Message
 ↓
🔓 Alice's Public Key
 │
 ↓
🔒 Ciphertext
```

---

# 2. Private Keys

A **private key** must be kept secret by its owner.

```text
Alice
  │
  └── 🔐 Private Key
          ↓
       KEEP SECRET
```

If Alice's private key is exposed, an attacker may be able to impersonate Alice or decrypt information, depending on how the key is being used.

### Simple rule

> **Public key → Share it**

> **Private key → Protect it**

---

# 3. Key Exchange

One of the major challenges in symmetric encryption is:

> **How do two people securely establish a shared secret key?**

Asymmetric cryptography can help solve this problem.

### Simplified example

Alice and Bob want to communicate securely.

```text
Alice                              Bob
  │                                  │
  │ ← Public information →           │
  │                                  │
  │     Key exchange process         │
  │                                  │
  └──────── Shared Secret ───────────┘
                  🔑
```

A commonly used technique is **Diffie-Hellman key exchange** and its modern elliptic-curve variants such as **ECDH**.

The important idea is:

```text
Alice + Bob
     ↓
Key exchange
     ↓
Shared secret
     ↓
Symmetric encryption
```

This is important because asymmetric cryptographic operations are generally more computationally expensive than symmetric encryption.

### In real systems

A common pattern is:

```text
Asymmetric cryptography
        ↓
Establish/protect session key
        ↓
Symmetric cryptography
        ↓
Encrypt actual data
```

This is called **hybrid cryptography**.

---

# 4. Digital Trust

Here's an important problem:

Suppose you receive a public key claiming:

```text
"This public key belongs to Google."
```

How do you know the key really belongs to Google?

Someone could create a fake key and claim:

```text
"I'm Google."
```

This is where **digital certificates** and **Certificate Authorities (CAs)** become important.

### Simplified certificate process

```text
Website
   ↓
Public Key
   ↓
Digital Certificate
   ↓
Certificate Authority (CA)
   ↓
Browser checks certificate
   ↓
Establish trust
```

A digital certificate can associate a public key with an identity/domain under a certificate authority's trust system.

---

## HTTPS example

When you visit:

```text
https://example.com
```

your browser performs cryptographic checks involving the server's certificate.

Simplified:

```text
Browser
   │
   │ "Who are you?"
   ↓
Website
   │
   │ Certificate + Public Key
   ↓
Browser
   │
   │ Verify certificate
   ↓
Trusted connection
```

If certificate validation fails, the browser may show a security warning.

# 5. Practical Applications

Asymmetric cryptography is used in many security systems.

## 1. HTTPS / TLS

HTTPS uses asymmetric cryptography as part of establishing a secure connection.

Simplified:

```text
Browser
   ↓
Asymmetric cryptography
   ↓
Establish secure session
   ↓
Symmetric encryption
   ↓
Exchange application data
```

---

## 2. Digital signatures

Asymmetric cryptography can also be used for **digital signatures**.

Here the purpose is different from encryption.

A person can use their **private key to create a signature**, and others can use the corresponding **public key to verify it**.

```text
Document
   ↓
Private Key 🔐
   ↓
Digital Signature
   ↓
Send document + signature
   ↓
Public Key 🔓
   ↓
Verify
```

This can provide:

* **Authenticity** — evidence that the signature corresponds to the private key
* **Integrity** — detection of changes to the signed data

### Important

Don't think:

> "Private key always means decryption."

Private/public key pairs can be used in different cryptographic schemes and operations. **Encryption and digital signatures are different purposes.**

---

## 3. SSH

SSH commonly uses public/private key pairs for secure authentication.

For example:

```text
Your computer
     │
     │ SSH
     ↓
Remote server
```

You may have:

```text
id_ed25519       ← Private key 🔐
id_ed25519.pub   ← Public key 🔓
```

The private key stays on your computer.

The public key can be installed on the server.

---

## 4. Software signing

Developers can digitally sign software or updates.

```text
Software
   ↓
Developer's Private Key
   ↓
Digital Signature
```

A system can use the corresponding public key to verify the signature.

This helps detect unauthorized modification and verify the expected signing identity.

---

# 🔥 Asymmetric vs Symmetric

This is very important for your cryptography fundamentals.

| Feature               | Symmetric         | Asymmetric                         |
| --------------------- | ----------------- | ---------------------------------- |
| Keys                  | One shared secret | Public + private pair              |
| Public key            | ❌                 | ✅                                  |
| Private key           | ❌                 | ✅                                  |
| Speed                 | Generally faster  | Generally slower                   |
| Large data encryption | ✅ Common          | Usually not the main use           |
| Key establishment     | More challenging  | Can help establish/protect secrets |
| Digital signatures    | ❌                 | ✅                                  |
| Examples              | AES, ChaCha20     | RSA, ECC, Ed25519                  |

# 🔐 One Important Real-World Concept

Modern secure communication often combines **both** types.

For example:

```text
        HTTPS / TLS
             │
             ↓
     Asymmetric cryptography
             │
             ↓
     Establish/protect keys
             │
             ↓
      Symmetric session key
             │
             ↓
     Encrypt actual traffic
             │
             ↓
        🔒 Secure data
```

So don't think **symmetric vs asymmetric = one must replace the other**.

In modern systems, they often **work together**.

### Final revision

```text
1. Public key     → Can be shared
2. Private key    → Must be protected
3. Key exchange   → Helps establish shared secrets
4. Digital trust  → Certificates + CA trust systems
5. Applications   → HTTPS, SSH, digital signatures, software signing
```
