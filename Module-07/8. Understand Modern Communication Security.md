# 8. Understand Modern Communication Security

**Modern communication security** means protecting data while it travels between devices, websites, servers, and applications.

Example:

```text
Your Computer
      ↓
  Secure Connection
      ↓
Web Server
```

---

## 1. TLS Handshake

The **TLS handshake** is the process used to establish a secure TLS connection.

A simplified version:

```text
Client (Browser)             Server
      |                         |
      | ---- ClientHello -----> |
      | <---- ServerHello ------ |
      | <---- Certificate ------ |
      |                         |
      |  Verify certificate     |
      |                         |
      | ==== Key agreement ==== |
      |                         |
      | <== Secure connection ==>|
```

### Simple steps

**Step 1 — ClientHello**

The browser tells the server that it wants to establish a TLS connection.

**Step 2 — ServerHello**

The server selects compatible cryptographic settings and responds.

**Step 3 — Certificate**

The server sends its certificate.

**Step 4 — Certificate verification**

The browser checks whether the certificate can be trusted.

**Step 5 — Key establishment**

Both sides establish cryptographic keys for the connection.

**Step 6 — Secure communication**

Encrypted communication begins.

> Modern TLS versions use more efficient and secure handshake mechanisms than older protocols.

# 2. Certificate Validation

Before trusting an HTTPS connection, the browser validates the server's certificate.

Important checks include:

### ① Certificate validity

The certificate must not be expired or not-yet-valid.

```text
Start Date ───────── End Date
              ↑
           Current date
```

### ② Domain name

The certificate must be valid for the website's domain.

For example:

```text
Certificate → example.com
Website     → example.com
```

This is expected.

### ③ Trusted CA

The certificate normally needs to chain to a **trusted Certificate Authority (CA)**.

```text
Website Certificate
        ↓
Intermediate CA
        ↓
Trusted Root CA
```

### ④ Digital signature

The browser verifies the certificate's cryptographic signature.

### ⑤ Certificate chain

The browser checks whether the chain from the website certificate to a trusted root is valid.

If important validation checks fail, the browser can display a security warning.

# 3. Secure Browsing

**Secure browsing** means using websites and browsers in ways that reduce communication and account-security risks.

### Good practices

* Use **HTTPS** websites.
* Keep your browser updated.
* Don't ignore certificate/security warnings.
* Avoid entering sensitive information on suspicious websites.
* Use strong, unique passwords.
* Enable multi-factor authentication where available.
* Be careful with unknown links and downloads.
* Avoid using untrusted networks for sensitive activities unless appropriate protections are in place.

### Example

```text
🔒 https://example.com
```

The lock indicates that the browser has established HTTPS, but **HTTPS alone does not mean the website itself is trustworthy**. A malicious or fraudulent website can also use HTTPS.

# 4. Encryption in Transit

**Encryption in transit** means protecting data while it is traveling from one system to another.

Without encryption:

```text
Computer ─── Data ───→ Server
                 ↑
            Attacker may
            try to observe
```

With TLS:

```text
Computer ── Encrypted Data ──→ Server
```

For example, when you submit:

```text
Username: user123
Password: ********
```

over HTTPS, TLS protects the network communication from being read by ordinary network observers.

### Important distinction

**Encryption in transit** protects data while moving.

**Encryption at rest** protects stored data.

```text
In transit → Data moving
At rest    → Data stored
```

# 5. Security Weaknesses and Mitigation

Communication security can have weaknesses. Understanding them helps us reduce risk.

| Weakness                      | Possible protection                              |
| ----------------------------- | ------------------------------------------------ |
| Old TLS/SSL versions          | Use modern TLS versions                          |
| Expired certificate           | Renew certificates                               |
| Invalid certificate           | Don't ignore browser warnings                    |
| Weak cryptographic algorithms | Use modern recommended algorithms                |
| Outdated browser              | Keep browser updated                             |
| Untrusted Wi-Fi               | Use HTTPS and appropriate secure networking      |
| Man-in-the-middle attempts    | Proper TLS certificate validation                |
| Phishing websites             | Check domain carefully; don't rely only on HTTPS |
| Poor server configuration     | Harden and regularly test the server             |

### Man-in-the-Middle Example

An attacker tries to place themselves between the user and server:

```text
User
  ↓
Attacker
  ↓
Server
```

Proper TLS authentication and certificate validation are designed to help prevent the attacker from impersonating the legitimate server.
