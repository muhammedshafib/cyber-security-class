# 1. Understand Web Fundamentals

Web fundamentals are the **foundation of web development and web security**. Before learning topics like HTTP security, authentication, APIs, OWASP, or web penetration testing, you should understand what happens when you open a website.

---

## 1. How Websites Work

A website is a collection of resources and programs that communicate over a network.

When you type:

```text
https://example.com
```

into a browser, several things happen.

### Step 1 — You enter the URL

A URL identifies the resource you want.

Example:

```text
https://example.com/login
```

It contains:

```text
https://      → Protocol
example.com  → Domain
/login       → Path
```

---

### Step 2 — DNS finds the server

Your computer needs an IP address to communicate with the website.

DNS means:

**Domain Name System**

It converts:

```text
example.com
```

into something like:

```text
93.184.216.34
```

Conceptually:

```text
Browser
   ↓
DNS
   ↓
IP address
```

---

### Step 3 — Connection is established

For HTTPS websites, the browser establishes a secure connection with the server.

Simplified:

```text
Browser
   ↓
Internet
   ↓
Web Server
```

HTTPS provides encryption for the communication between the browser and server.

---

### Step 4 — Browser sends an HTTP request

For example:

```http
GET / HTTP/1.1
Host: example.com
```

The request tells the server what the browser wants.

Common HTTP methods include:

| Method | Purpose               |
| ------ | --------------------- |
| GET    | Retrieve data         |
| POST   | Send/create data      |
| PUT    | Replace/update data   |
| PATCH  | Partially update data |
| DELETE | Delete data           |

---

### Step 5 — Server processes the request

The server receives the request.

It may:

* check authentication
* execute application code
* query a database
* process input
* communicate with another service
* generate a response

---

### Step 6 — Server sends a response

Example:

```http
HTTP/1.1 200 OK
Content-Type: text/html
```

The response may contain:

```html
<html>
    <body>
        <h1>Hello</h1>
    </body>
</html>
```

---

### Step 7 — Browser renders the page

The browser processes:

```text
HTML
CSS
JavaScript
Images
Fonts
```

and turns them into the webpage you see.

### Complete basic flow

```text
User
 ↓
Browser
 ↓
DNS
 ↓
IP address
 ↓
Internet
 ↓
Web Server
 ↓
Application
 ↓
Database
 ↓
Application
 ↓
Web Server
 ↓
Browser
 ↓
Webpage
```

---

# 2. Client-Server Architecture

The **client-server model** is one of the most important concepts in web technology.

### Client

The client is normally the software requesting a service.

Examples:

* Chrome
* Firefox
* Edge
* Mobile application
* JavaScript application

### Server

The server provides the requested service.

Examples:

* Web server
* Application server
* Database server
* API server

Basic model:

```text
             Request
Client --------------------> Server
       <--------------------
             Response
```

### Example

You open:

```text
https://example.com/profile
```

Your browser sends:

```text
GET /profile
```

The server processes it and sends back the required information.

---

## Client-side

Client-side code runs primarily in the user's browser.

Common technologies:

```text
HTML
CSS
JavaScript
```

Example:

```javascript
document.getElementById("message").textContent = "Hello";
```

The browser executes this code.

---

## Server-side

Server-side code runs on the server.

Common technologies include:

```text
Python
Java
JavaScript / Node.js
PHP
C#
Ruby
Go
```

Example:

```text
Browser
   ↓
POST /login
   ↓
Backend
   ↓
Check username/password
   ↓
Database
   ↓
Login result
```

The user normally doesn't directly see the server-side source code.

# 3. Frontend and Backend Concepts

A modern web application is commonly divided into **frontend** and **backend**.

## Frontend

The frontend is what the user interacts with.

Examples:

* buttons
* menus
* forms
* images
* dashboards
* navigation
* animations

Main technologies:

```text
HTML → Structure
CSS → Appearance
JavaScript → Behaviour
```

Think:

> **Frontend = what the user sees and interacts with.**

---

## Backend

The backend handles application logic and data processing.

For example, when you log in:

```text
Frontend
   ↓
Username + Password
   ↓
Backend
   ↓
Authentication logic
   ↓
Database
   ↓
Result
   ↓
Frontend
```

Think:

> **Backend = what happens behind the scenes.**

---

## Database

The database stores application data.

For example:

```text
Users
----------------
id
username
email
password_hash
created_at
```

Other examples:

```text
Products
Orders
Messages
Payments
Sessions
Logs
```

Common databases:

* MySQL
* PostgreSQL
* Microsoft SQL Server
* MongoDB
* SQLite

# 4. Web Application Workflows

A **web application workflow** describes how different components interact to complete an operation.

Let's take a login system.

## Login workflow

### Step 1

User opens:

```text
/login
```

### Step 2

Frontend displays:

```text
Username: _______

Password: _______

[ Login ]
```

### Step 3

User enters credentials.

Example:

```text
username = alice
password = ********
```

### Step 4

Browser sends a request:

```http
POST /login
```

with the submitted information.

### Step 5

Backend receives it.

```text
Backend
   ↓
Validate input
   ↓
Find user
   ↓
Check password
```

### Step 6

Backend communicates with the database.

```text
Backend → Database
```

The database returns the relevant user information.

### Step 7

Backend determines whether authentication succeeds.

```text
Valid
  ↓
Create authenticated session/token
```

### Step 8

Browser receives the response.

The user may then see:

```text
Welcome, Alice
```

# 5. Modern Web Architecture

Modern websites are often much more complicated than:

```text
Browser → One Server
```

A modern application may look like:

```text
                    ┌──────────────┐
                    │   Browser    │
                    └──────┬───────┘
                           │
                           ↓
                    ┌──────────────┐
                    │     CDN      │
                    └──────┬───────┘
                           │
                           ↓
                    ┌──────────────┐
                    │Load Balancer │
                    └──────┬───────┘
                           │
              ┌────────────┼────────────┐
              ↓            ↓            ↓
         Web Server    Web Server    Web Server
              │            │            │
              └────────────┼────────────┘
                           ↓
                    ┌──────────────┐
                    │ API/Backend  │
                    └──────┬───────┘
                           │
             ┌─────────────┼─────────────┐
             ↓             ↓             ↓
         Database       Cache       Other APIs
```

Let's understand the important components.

---

## A. CDN

**CDN = Content Delivery Network**

It helps deliver static content closer to users.

Examples:

```text
Images
CSS
JavaScript
Videos
Fonts
```

Instead of every request going directly to the main server, some content can be delivered through CDN infrastructure.

---

## B. Load Balancer

A load balancer distributes requests among multiple servers.

Instead of:

```text
1000 users
    ↓
One server
```

you can have:

```text
             Load Balancer
             /     |     \
            ↓      ↓      ↓
         Server  Server  Server
```

This helps applications handle large amounts of traffic.

---

## C. API

An API allows software components to communicate.

For example:

```text
Frontend
   ↓
GET /api/products
   ↓
Backend API
   ↓
Database
```

The API may return JSON:

```json
{
  "id": 101,
  "name": "Laptop",
  "price": 75000
}
```

APIs are extremely important in modern web security.

---

## D. Database

The backend may communicate with one or more databases.

Example:

```text
Backend
   ↓
Database
```

or:

```text
Backend
 ├── User Database
 ├── Product Database
 └── Order Database
```

---

## E. Cache

A cache temporarily stores frequently accessed data.

Example:

```text
User
 ↓
Backend
 ↓
Cache
 ↓
Data
```

If the data isn't available in the cache:

```text
Backend
 ↓
Database
 ↓
Cache
 ↓
User
```

Popular technologies include Redis and Memcached.

---

## F. Microservices

A large application may be divided into smaller services.

For example:

```text
                 Application
                     |
       ┌─────────────┼─────────────┐
       ↓             ↓             ↓
 User Service   Payment Service  Order Service
       │             │             │
       ↓             ↓             ↓
   User DB       Payment DB      Order DB
```

Each service performs a specific function.

# Security Perspective

For cybersecurity, you should eventually be able to look at this:

```text
Browser
   ↓
HTTPS
   ↓
CDN
   ↓
Load Balancer
   ↓
Web Server
   ↓
API
   ↓
Application Logic
   ↓
Database
```

and ask:

> **What data is moving at each stage, who is allowed to access it, and how is each component protected?**

That question leads directly into topics such as:

```text
HTTP security
Authentication
Authorization
Session security
Input validation
SQL injection
XSS
CSRF
SSRF
API security
Access-control vulnerabilities
OWASP Top 10
Web penetration testing
```

### The core mental model

Remember these five points:

**1. Website** → collection of web resources and application functionality.

**2. Client** → requests services, usually the browser.

**3. Server** → processes requests and returns responses.

**4. Frontend** → user-facing part.

**5. Backend** → server-side logic, data processing, and services.

And the basic communication pattern is:

```text
        REQUEST
Browser ───────────────→ Server
        ←───────────────
        RESPONSE
```

That request/response cycle is the **core foundation of the web**.
