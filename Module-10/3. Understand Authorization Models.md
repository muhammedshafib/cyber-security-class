# 3. Understand Authorization Models 🔐

Authorization is the process of deciding what an authenticated user is allowed to access or do in a system.

In simple words, authentication checks who you are, while authorization checks what you can do.

Example: You log in to AWS successfully, but you can only view resources, not delete them. This is authorization.

## 1. Role-Based Access Control (RBAC)

Meaning: RBAC is an access control method where permissions are assigned based on a user's job role.

In simple words, different people get different permissions based on their job responsibilities.

Example: Company

| Role          | Permissions                        |
| ------------- | ---------------------------------- |
| Administrator | Manage users and resources         |
| Developer     | Create and manage applications     |
| Employee      | Access normal company applications |
| Viewer        | Only view information              |

How it works:

1. Create roles.
2. Assign permissions to each role.
3. Assign roles to users.
4. Users receive permissions through their roles.

Why is RBAC important?

- Easy permission management.
- Reduces unauthorized access.
- Saves time when managing many users.
- Helps maintain security.

## 2. Principle of Least Privilege (PoLP)

Meaning: Give users only the minimum permissions they need to perform their jobs.

In simple words, don't give unnecessary access to anyone.

Example:

A company employee only needs to read reports.

- Correct permission: View reports.
- Unnecessary permission: Delete reports.
- Dangerous permission: Administrator access to the entire system.

Why is it important?

1. Prevents unauthorized activities.
2. Reduces damage if an account is hacked.
3. Protects sensitive information.
4. Reduces the risk of privilege misuse.

Remember: Give only the access required, nothing extra.

## 3. Access management

Meaning: Access management is the process of controlling, monitoring, and managing who can access systems, applications, and data.

Example:

In an AWS company account:

- Administrator creates user accounts.
- Developer receives access to development resources.
- Employee receives access to company applications.
- When an employee leaves, their access is removed.

### Main activities

1. Create user accounts.
2. Assign roles and permissions.
3. Monitor user activities.
4. Review access regularly.
5. Remove unnecessary access.

Why is it important?

It helps prevent unauthorized access and keeps company resources secure.

## 4. Permission assignment

Meaning: Permission assignment is the process of giving users or roles specific rights to perform actions on resources.

In simple words, it decides what actions a user can perform.

### Common permissions

| Permission | Meaning                          |
| ---------- | -------------------------------- |
| Read       | View information                 |
| Write      | Create or modify information     |
| Delete     | Remove information               |
| Execute    | Run a program or command         |
| Admin      | Manage system settings and users |

Example:

Suppose an employee works with company files.

- Read: Can view files.
- Write: Can edit files.
- Delete: Can delete files.
- Admin: Can manage access and settings.

### How are permissions assigned?

1. Identify the user's job requirements.
2. Select the appropriate role.
3. Assign necessary permissions.
4. Check whether access works correctly.
5. Review permissions regularly.

Important: Permissions can be assigned directly to users or through roles and groups, depending on the system.

## 5. Security implications

Meaning: Security implications are the possible security risks or consequences of incorrect authorization and permission management.

In simple words, what problems can happen if users receive the wrong permissions?

### Common security risks

| Risk                  | Simple explanation                            |
| --------------------- | --------------------------------------------- |
| Excessive permissions | Users receive more access than required       |
| Privilege escalation  | A normal user gains higher-level permissions  |
| Unauthorized access   | Someone accesses resources without approval   |
| Data leakage          | Sensitive information is exposed              |
| Insider threats       | An employee misuses their authorized access   |
| Account compromise    | An attacker takes control of a user's account |

### Real-world scenario

Imagine a company gives every employee administrator access to its AWS account.

An employee accidentally deletes an important database.

What went wrong?

- Too many permissions were given.
- Least privilege was not followed.
- Access management was weak.

How can we prevent this?

1. Apply least privilege.
2. Use RBAC.
3. Review permissions regularly.
4. Enable MFA.
5. Monitor user activities.
6. Remove unnecessary permissions.

## Important interview questions

1\. What is RBAC?

RBAC is an authorization model that assigns permissions to users based on their job roles.

2\. What is the principle of least privilege?

It means giving users only the minimum permissions required to perform their work.

3\. What is privilege escalation?

Privilege escalation occurs when a user gains permissions beyond their authorized level.

4\. What happens if everyone gets administrator access?

It increases security risks, accidental damage, unauthorized changes, and data exposure.

5\. What is the difference between authentication and authorization?

- Authentication verifies identity.
- Authorization determines access permissions.

Final concept to remember

Authorization is about controlling access. RBAC decides access based on roles, least privilege limits unnecessary access, permission assignment gives specific rights, and access management controls the complete process.
