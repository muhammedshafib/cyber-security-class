4. Understand Active Directory Fundamentals
1. What is Active Directory (AD)?

Active Directory (AD) is Microsoft's directory service used to manage and organise users, computers, groups, and other network resources within an organisation.

Key Functions:
Centralised user authentication and authorisation
Resource management (printers, shared folders, applications)
Security policy enforcement
Single Sign-On (SSO) capabilities
Example:

Instead of creating separate accounts on every computer, an organisation creates a user account once in Active Directory. Users can then log in to any domain-joined computer using the same credentials.

2. Domains

A Domain is a logical container within Active Directory that stores users, computers, groups, and other objects that share a common database and security policies.

Characteristics:
Provides a centralised administration boundary
Uses a unique DNS name (e.g., company.local or contoso.com)
Allows users to authenticate across the network
Example:

Domain: contoso.com

Objects inside the domain:

Users: John, Sarah
Computers: PC01, PC02
Servers: DC01, FILE01
contoso.com
│
├── Users
├── Computers
└── Servers

3. Domain Controllers (DCs)

A Domain Controller is a server that hosts the Active Directory database and authenticates users and computers in the domain.

Responsibilities:
Verifies usernames and passwords
Maintains the Active Directory database
Enforces security policies
Replicates directory information with other DCs
Example Authentication Process:
User enters username and password.
Computer sends the request to the Domain Controller.
DC verifies credentials.
If valid, access is granted.
User → Computer → Domain Controller → Authentication

Benefits of Multiple DCs:
High availability
Fault tolerance
Load balancing
4. Organizational Units (OUs)

An Organizational Unit (OU) is a container within a domain used to organise objects and simplify administration.

Why Use OUs?
Group similar objects together
Delegate administrative control
Apply Group Policies to specific departments
Example Structure:
contoso.com
│
├── Sales OU
│   ├── Users
│   └── Computers
│
├── HR OU
│   ├── Users
│   └── Computers
│
└── IT OU
    ├── Users
    └── Computers

Benefits:
Easier management
Department-specific policies
Reduced administrative complexity
5. Group Policies (GPOs)

Group Policy is a feature that allows administrators to configure and enforce settings on users and computers across the domain.

Common Uses:
Enforce password policies
Disable Control Panel access
Configure desktop settings
Deploy software
Map network drives
Configure security settings
Example:

An administrator wants all employees to:

Use passwords with at least 12 characters
Change passwords every 90 days

A Group Policy is created and linked to the domain, automatically applying these settings to all users.

GPO Processing Flow:
Group Policy Object (GPO)
          ↓
Linked to Domain/OU
          ↓
Applied to Users & Computers
          ↓
Settings Enforced

Quick Summary
Component	PurposeActive Directory	Centralised directory and identity management
Domain	Administrative and security boundary
Domain Controller	Authenticates users and stores AD database
Organizational Unit (OU)	Organises objects within a domain
Group Policy (GPO)	Applies configurations and security settings
Memory Tip

Think of a company hierarchy:

Active Directory = Entire company database
Domain = Company building
Domain Controller = Security desk at the entrance
OU = Different departments (HR, Sales, IT)
Group Policy = Company rules and regulations

This analogy helps visualise how Active Directory components work together to manage users, computers, and security across an organisation.
