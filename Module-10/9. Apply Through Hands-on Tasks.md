# 9. Apply Through Hands-on Tasks

This section focuses on applying your IAM (Identity and Access Management) knowledge through practical security exercises.

As an IAM security analyst, your job is to understand how users authenticate, check their permissions, investigate suspicious activities, identify identity risks, and prepare security reports.

We will practise all five tasks using simple examples and Python where useful.

## 1. Analyze Authentication Logs

What is it?

Authentication log analysis means examining login records to identify normal and suspicious authentication activities.

Why is it important?

- Detect repeated failed login attempts.
- Identify possible brute-force attacks.
- Find unusual login times.
- Detect suspicious login patterns.
- Identify potentially compromised accounts.

Example authentication log:

```
2026-11-05 09:00:12 user1 LOGIN_SUCCESS 192.168.1.10
2026-11-05 09:05:22 user2 LOGIN_FAILED  192.168.1.20
2026-11-05 09:05:30 user2 LOGIN_FAILED  192.168.1.20
2026-11-05 09:05:38 user2 LOGIN_FAILED  192.168.1.20
2026-11-05 09:06:10 user2 LOGIN_SUCCESS 192.168.1.20
```

Investigation:

- user1: Successful login.
- user2: Three failed login attempts followed by a successful login.
- IP address `192.168.1.20`: Requires further investigation.


## 2. Review Access Control Scenarios

What is it?

Access control review means checking whether users have the correct permissions to access systems, applications, and sensitive information.

Why is it important?

- Prevent unauthorized access.
- Identify excessive permissions.
- Apply least privilege.
- Protect sensitive information.

Practical scenario:

| User       | Assigned permission | Job requirement |
| ---------- | ------------------- | --------------- |
| Employee 1 | Read access         | Read files      |
| Employee 2 | Administrator       | View reports    |
| Employee 3 | Write access        | Edit documents  |
| Employee 4 | Administrator       | Manage servers  |

Your investigation:

- Employee 1: Appropriate access.
- Employee 2: Excessive access. Review administrator privileges.
- Employee 3: Appropriate access.
- Employee 4: Appropriate if server administration is part of the job.

Important concept: Just because someone has access does not mean they need that access.

## 3. Investigate Suspicious Login Activities

What is it?

Suspicious login investigation means examining unusual authentication activities to determine whether an account is being misused or compromised.

Common suspicious activities:

1. Multiple failed login attempts.
2. Login from an unusual country.
3. Login at an unusual time.
4. Successful login after repeated failures.
5. Login from an unfamiliar device or IP address.

Practical scenario:

A user normally logs in between 9 AM and 6 PM. Suddenly, the account has a successful login at 2 AM, followed by access to sensitive files.

Investigation process:

1. Identify the suspicious login event.
2. Check the username and IP address.
3. Verify the login date and time.
4. Review previous authentication attempts.
5. Check the user's access activities.
6. Determine whether the activity is legitimate or suspicious.
7. Escalate or contain the incident according to the organization's procedure.


## 4. Assess Identity Risks

What is it?

Identity risk assessment means identifying weaknesses in user accounts, authentication systems, and access permissions that attackers could exploit.

Common identity risks:

| Risk                        | Explanation                                       |
| --------------------------- | ------------------------------------------------- |
| Weak passwords              | Easily guessed passwords                          |
| No MFA                      | Accounts lack an additional authentication factor |
| Excessive privileges        | Users have more permissions than required         |
| Inactive accounts           | Unused accounts remain enabled                    |
| Shared accounts             | Multiple people use one account                   |
| Privileged account exposure | Administrator accounts are not properly protected |

Practical scenario:

You are reviewing an organization's IAM environment.

| Account | Security condition | Risk   |
| ------- | ------------------ | ------ |
| Admin01 | No MFA             | High   |
| User02  | Weak password      | High   |
| User03  | Inactive account   | Medium |
| User04  | Read-only access   | Low    |

Your recommendations:

1. Enable MFA for administrator accounts.
2. Enforce strong password policies.
3. Disable unnecessary inactive accounts after verification.
4. Remove excessive permissions.
5. Monitor privileged account activities.

Important concept: Identify the risk, evaluate its impact, and recommend appropriate security controls.

## 5. Create IAM Security Reports

What is it?

An IAM security report is a document that explains identity-related security findings, risks, investigation results, and recommendations.

Why is it important?

- Communicates security findings.
- Documents suspicious activities.
- Helps management understand identity risks.
- Tracks security improvements.
- Provides evidence for security audits.

Practical IAM Security Report:

## IAM Security Assessment Report

PRACTICAL LAB REPORT | 05 NOVEMBER 2026

1\. Objective

To analyze authentication activities, review access permissions, and identify identity-related security risks.

2\. Findings

- Multiple failed login attempts detected.
- One account has excessive administrator permissions.
- MFA is not enabled on an administrator account.
- An inactive user account remains enabled.

3\. Risk Assessment

| Finding                | Risk level |
| ---------------------- | ---------- |
| Repeated failed logins | High       |
| Excessive privileges   | High       |
| Missing MFA            | High       |
| Inactive account       | Medium     |

4\. Recommendations

- Investigate repeated failed login attempts.
- Apply least privilege.
- Enable MFA.
- Review and disable unnecessary inactive accounts.

5\. Conclusion

The assessment identified several identity security weaknesses. Implementing the recommended controls will help improve authentication security and access management.

Prepared by: IAM Security Analyst (Training Exercise)
