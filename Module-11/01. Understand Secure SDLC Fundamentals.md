# Module 1: Understand Secure SDLC Fundamentals 🔐

This topic is an important foundation of Application Security (AppSec) and Ethical Hacking. As an aspiring Red Team professional, understanding Secure SDLC helps you identify security weaknesses at every stage of software development.

Let's learn from beginner to advanced, with simple explanations, examples, and practical scenarios.

## 1. What is SDLC?

Beginner level

SDLC stands for Software Development Life Cycle.

SDLC is a step-by-step process used to develop software or applications, from the initial idea until deployment and maintenance.

In simple words:

SDLC is the complete journey of creating software.

Example: Imagine a company wants to develop an online banking application.

It follows these stages:

## SDLC Life Cycle

1. Planning

   Decide what application to build and why.

   Example: Plan an online banking application.
2. Requirement Analysis

   Identify what users and the business need.

   Example: Login, money transfer, account balance.
3. Design

   Create the application architecture and database design.

   Example: Design secure login and payment systems.
4. Development

   Developers write the actual source code.

   Example: Build login functionality using Python or Java.
5. Testing

   Check whether the application works correctly.

   Example: Test login, payments and security vulnerabilities.
6. Deployment

   Release the application for real users.

   Example: Launch the banking application.
7. Maintenance

   Monitor, update and fix problems.

   Example: Fix security bugs and install updates.

Why is SDLC important?

- Organizes software development.
- Improves software quality.
- Reduces development costs.
- Helps identify problems early.
- Makes software easier to maintain.

## 2. Secure SDLC Concepts

Beginner to intermediate

Secure SDLC (SSDLC) means integrating security into every stage of software development.

Normal SDLC focuses on building functional software.

Secure SDLC focuses on building functional and secure software.

Example:

Imagine developers create a banking login page.

Normal SDLC:

- Create username and password fields.
- Develop login functionality.
- Test whether login works.

Secure SDLC:

- Use secure password storage.
- Implement Multi-Factor Authentication (MFA).
- Protect against SQL Injection.
- Use HTTPS.
- Implement account lockout and rate limiting.
- Test authentication security.

### Important Secure SDLC concepts

| Concept                  | Meaning                                      |
| ------------------------ | -------------------------------------------- |
| Security by Design       | Include security from the beginning          |
| Threat Modeling          | Identify possible attacks before development |
| Secure Coding            | Write code following security practices      |
| Security Testing         | Find vulnerabilities in applications         |
| Vulnerability Management | Track and fix security weaknesses            |
| Least Privilege          | Give users only necessary permissions        |
| Defense in Depth         | Use multiple security protection layers      |

Important security testing methods:

- SAST: Static Application Security Testing.
- DAST: Dynamic Application Security Testing.
- SCA: Software Composition Analysis.
- Penetration Testing: Simulate authorized attacks to identify weaknesses.

## 3. Security Throughout Development

Intermediate level

Security must be included in every SDLC stage, not just during final testing.

| SDLC stage   | Security activity                              |
| ------------ | ---------------------------------------------- |
| Planning     | Identify security requirements                 |
| Requirements | Define authentication and access controls      |
| Design       | Threat modeling and secure architecture        |
| Development  | Secure coding and code reviews                 |
| Testing      | Vulnerability scanning and penetration testing |
| Deployment   | Secure configuration and HTTPS                 |
| Maintenance  | Monitoring, patching and incident response     |

## 4. Security Responsibilities

Intermediate level

Security is not the responsibility of only one person. Every team member has a role.

| Role               | Security responsibility                   |
| ------------------ | ----------------------------------------- |
| Project Manager    | Ensure security requirements are included |
| Security Architect | Design secure application architecture    |
| Developer          | Write secure code                         |
| Security Engineer  | Implement security controls               |
| QA Tester          | Test functionality and security           |
| Penetration Tester | Identify exploitable vulnerabilities      |
| DevOps Engineer    | Secure deployment and infrastructure      |
| SOC Analyst        | Monitor suspicious activities             |

### Example: Who is responsible for SQL Injection?

Imagine a developer creates a login system with unsafe SQL queries.

- Developer: Must use parameterized queries.
- Security Engineer: Reviews application security.
- QA Tester: Tests input handling.
- Penetration Tester: Attempts authorized SQL Injection testing.
- Project Manager: Ensures the vulnerability is fixed before release.

Important: Security is a shared responsibility.

## 5. Risk Reduction Strategies

Intermediate to advanced

Risk reduction means taking steps to decrease the possibility and impact of security incidents.

### Important strategies

1\. Threat Modeling

Identify possible attackers, attack methods and vulnerable components before development.

Example: Identify the possibility of an attacker accessing another customer's account.

2\. Secure Coding

Follow secure programming practices.

Example:

- Input validation.
- Parameterized SQL queries.
- Secure password hashing.
- Proper error handling.

3\. Access Control

Restrict access to sensitive information.

Example: A normal customer must not access administrator functionality.

4\. Security Testing

Perform security assessments throughout development.

Tools:

- Burp Suite
- OWASP ZAP
- Semgrep
- Nmap

5\. Patch Management

Regularly update software, libraries and operating systems to fix known vulnerabilities.

6\. Security Monitoring

Monitor logs and application activities to identify suspicious behavior.

7\. Backup and Recovery

Maintain backups and prepare recovery procedures in case of an attack.

### Risk assessment example

| Vulnerability         | Possible impact                  | Risk reduction            |
| --------------------- | -------------------------------- | ------------------------- |
| SQL Injection         | Database compromise              | Parameterized queries     |
| Weak passwords        | Account takeover                 | MFA and password policies |
| Broken access control | Unauthorized data access         | Server-side authorization |
| Outdated libraries    | Known vulnerability exploitation | Dependency updates        |
| Misconfiguration      | Sensitive data exposure          | Secure configuration      |
