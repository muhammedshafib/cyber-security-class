# **8. AI-Assisted Secure Development**

AI-Assisted Secure Development means using Artificial Intelligence (AI) tools such as ChatGPT, GitHub Copilot, and other AI-powered security tools to help developers identify security weaknesses, improve code quality, assess risks, and build secure applications.

AI acts as a security assistant, but developers must verify its recommendations before implementing them.

## **1. Use AI For**

### **1.1 Security Code Reviews**

**Meaning:**

Using AI to examine source code and identify potential security vulnerabilities, insecure coding practices, and weaknesses.

**What AI can identify:**

- SQL Injection
- Cross-Site Scripting (XSS)
- Hardcoded passwords and API keys
- Weak authentication
- Insecure input validation
- Improper error handling

**Practical example:**

Vulnerable Python code:

```
username = input("Enter username: ")query = "SELECT * FROM users WHERE username = '" + username + "'"cursor.execute(query)
```

Ask AI:

```
Review this Python code for security vulnerabilities.
Identify possible attacks and provide a secure version.
Explain each security improvement.
```

AI may identify SQL Injection and recommend parameterized queries.

Secure version:

```
username = input("Enter username: ")query = "SELECT * FROM users WHERE username = ?"cursor.execute(query, (username,))
```

**Objective:** Find security vulnerabilities before deploying the application.

### **1.2 Threat Modeling Discussions**

**Meaning:**

Threat modeling is the process of identifying possible threats, understanding how attackers might exploit an application, and planning security controls.

AI can help developers:

- Identify possible attackers.
- Identify application entry points.
- Discover potential attack paths.
- Identify security threats.
- Recommend mitigation strategies.

**Practical example:**

Imagine developing a login application.

Ask AI:

```
Perform threat modeling for a web application login system.

Identify:
1. Possible attackers.
2. Attack surfaces.
3. Potential threats.
4. Security vulnerabilities.
5. Recommended security controls.
```

Possible threats:

| Threat              | Security solution         |
| ------------------- | ------------------------- |
| Brute-force attack  | Rate limiting             |
| SQL Injection       | Parameterized queries     |
| Password theft      | Secure password hashing   |
| Session hijacking   | Secure session management |
| Credential stuffing | MFA and login monitoring  |

**Objective:** Understand attacks before attackers discover weaknesses.

### **1.3 Security Architecture Reviews**

**Meaning:**

Using AI to review an application's overall security design and architecture.

AI can help review:

- Authentication architecture.
- Authorization mechanisms.
- Database security.
- API security.
- Network communication.
- Data encryption.
- Access control.

**Practical example:**

Ask AI:

```
Review the security architecture of my web application.

Architecture:
Frontend: React
Backend: Python Flask
Database: MySQL
Authentication: JWT

Identify:
1. Architecture weaknesses.
2. Potential attack scenarios.
3. Security risks.
4. Recommended security improvements.
```

**Objective:** Identify security weaknesses in application design before implementation.

### **1.4 Risk Assessments**

**Meaning:**

Using AI to identify, analyze, and prioritize security risks in an application.

AI can help determine:

- What could go wrong?
- How likely is the threat?
- What would be the impact?
- Which risks need immediate attention?
- What security controls can reduce the risk?

**Example:**

| Security risk            | Likelihood | Impact   | Priority |
| ------------------------ | ---------- | -------- | -------- |
| SQL Injection            | High       | Critical | Critical |
| Weak passwords           | Medium     | High     | High     |
| Missing security headers | Medium     | Medium   | Medium   |
| Information disclosure   | Low        | Medium   | Low      |

**Objective:** Prioritize security issues and reduce application risks.

## **2. Validate AI Outputs**

AI-generated security recommendations are not always correct. They can contain mistakes, outdated advice, incomplete fixes, or false positives.

Therefore, every AI-generated recommendation must be verified.

### **2.1 Verify Recommendations**

**Meaning:**

Check whether the security recommendation provided by AI is technically correct and appropriate for your application.

**How to verify:**

1. Understand the recommendation.
2. Check official documentation.
3. Review the affected source code.
4. Test the proposed solution.
5. Confirm that the vulnerability is resolved.

**Example:**

AI says:

"Use parameterized queries to prevent SQL Injection."

Verification:

- Check whether parameterized queries are implemented correctly.
- Test with SQL Injection test inputs in an authorized environment.
- Confirm that the application handles the inputs safely.

### **2.2 Review Security Implications**

**Meaning:**

Understand whether implementing an AI recommendation could introduce new security problems.

**Example:**

AI recommends disabling SSL certificate verification to fix a connection error.

```
requests.get(url, verify=False)
```

This is dangerous because it disables certificate verification and can expose communication to man-in-the-middle attacks.

A developer should reject this recommendation for normal production use and fix the certificate configuration instead.

**Objective:** Ensure that AI recommendations do not weaken application security.

### **2.3 Assess Implementation Risks**

**Meaning:**

Before implementing an AI-generated solution, evaluate whether it could break existing functionality, introduce vulnerabilities, or create operational problems.

**Example:**

AI recommends changing the authentication system.

Before implementation:

1. Review the existing authentication system.
2. Check compatibility with existing features.
3. Test the changes in a development environment.
4. Perform security testing.
5. Review the code.
6. Deploy only after successful validation.

**Objective:** Prevent new security problems while fixing existing ones.

## **3. Practical Hands-on Task**



Beginner-friendly project

**AI-Assisted Python Security Code Review**



**Requirements:**

- Python
- VS Code
- ChatGPT
- A small Python application

**Step 1: Create a vulnerable Python file**

Create `login.py`:

```
import sqlite3conn = sqlite3.connect("users.db")cursor = conn.cursor()username = input("Username: ")password = input("Password: ")query = f"SELECT * FROM users WHERE username='{username}' AND password='{password}'"cursor.execute(query)print(cursor.fetchall())conn.close()
```

**Step 2: Ask AI to review the code**

Use this prompt:

```
Act as an Application Security Engineer.

Review this Python login application.

Identify:
1. SQL Injection vulnerabilities.
2. Insecure password storage.
3. Authentication weaknesses.
4. Input validation problems.
5. Security improvements.

Provide:
- Vulnerability explanation.
- Severity.
- Possible attack scenario.
- Secure corrected code.
- Explanation of every correction.
```

**Step 3: Verify AI recommendations**

Check:

- Is SQL Injection properly prevented?
- Are passwords stored using secure password hashing?
- Is authentication handled correctly?
- Are errors handled safely?

**Step 4: Test the corrected code**

Use:

- Manual code review.
- Pytest.
- Bandit for Python security analysis.
- Authorized SQL Injection test cases.

**Step 5: Document your findings**

Create:

```
AI-Security-Review/
│
├── login.py
├── secure_login.py
├── test_login.py
└── SECURITY-REPORT.md
```

Document the original vulnerabilities, AI recommendations, your verification process, and the final fixes.

## **5. Interview Questions**

1. What is AI-assisted secure development?
2. How can AI help in security code reviews?
3. What is AI-assisted threat modeling?
4. How can AI help identify application security risks?
5. Why should AI-generated code always be reviewed?
6. What are false positives in AI security analysis?
7. Can AI-generated code introduce security vulnerabilities?
8. How do you validate AI-generated security recommendations?
9. What are the risks of blindly trusting AI-generated code?
10. Can AI replace application security engineers?

**Important interview answer:**

AI can assist developers in identifying vulnerabilities, performing threat modeling, reviewing architecture, and assessing security risks. However, AI cannot guarantee that an application is secure. Developers and security engineers must independently verify AI recommendations through code reviews, testing, and security validation.
