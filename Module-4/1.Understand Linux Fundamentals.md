# 1. Understand Linux Fundamentals

Linux Fundamentals means understanding the basic structure and working of a Linux operating system. For cybersecurity, Linux knowledge is very important because many servers, security tools, cloud systems, and cybersecurity platforms use Linux.

The five important areas are:

1. **Linux Ecosystem**
2. **File System Hierarchy**
3. **Users and Groups**
4. **Processes**
5. **System Services**

---

# A. Linux Ecosystem

## 1. What is Linux?

**Linux is an open-source operating system kernel** originally created by Linus Torvalds in 1991.

Strictly speaking:

* **Linux = Kernel**
* A complete Linux operating system is usually called a **Linux distribution (distro)**.
* A distro combines the Linux kernel with system utilities, libraries, package managers, desktop environments, and applications.

### Simple definition for exam

> Linux is an open-source, Unix-like operating system kernel that manages hardware resources and provides a platform for applications and system software.

### Malayalam

> Linux ഒരു **open-source, Unix-like operating system kernel** ആണ്. ഇത് computer hardware resources manage ചെയ്യുകയും applications-ന് പ്രവർത്തിക്കാനുള്ള environment നൽകുകയും ചെയ്യുന്നു.

---

## 2. What is the Linux Kernel?

The **kernel** is the core component of Linux.

It communicates between:

**User → Applications → Kernel → Hardware**

For example:

```text
User
 ↓
Application
 ↓
System Call
 ↓
Linux Kernel
 ↓
Hardware
```

The kernel manages:

* CPU
* RAM
* Storage
* Network interfaces
* Processes
* Devices
* Security permissions

### Malayalam

Kernel Linux-ന്റെ **heart/core component** ആണ്.

User നേരിട്ട് hardware manage ചെയ്യുന്നതിന് പകരം kernel ആണ്:

* CPU manage ചെയ്യുന്നത്
* RAM manage ചെയ്യുന്നത്
* Disk manage ചെയ്യുന്നത്
* Network manage ചെയ്യുന്നത്
* Processes manage ചെയ്യുന്നത്
* Hardware devices control ചെയ്യുന്നത്

# B. File System Hierarchy

Linux organizes files and directories in a tree structure.

The top of the Linux filesystem is:

```text
/
```

This is called the **root directory**.

It is different from the `/root` directory.

* `/` → top-level filesystem
* `/root` → home directory of the root user

---

## Important Linux Directories

### 1. `/`

The root of the entire filesystem.

Everything starts from `/`.

Example:

```bash
ls /
```

---

### 2. `/home`

Contains normal users' home directories.

Example:

```text
/home/shafi
/home/user1
```

A user's personal files are normally stored here.

### Malayalam

`/home` സാധാരണ users-ന്റെ personal directories സൂക്ഷിക്കുന്ന സ്ഥലമാണ്.

---

### 3. `/root`

Home directory of the **root user**.

```text
/root
```

Do not confuse:

```text
/
```

with:

```text
/root
```

---

### 4. `/etc`

Contains system configuration files.

Examples:

```text
/etc/passwd
/etc/group
/etc/hosts
/etc/ssh/
```

Very important for cybersecurity.

For example:

```bash
cat /etc/passwd
```

shows information about user accounts.

---

### 5. `/var`

Contains variable data that changes frequently.

Examples:

* Logs
* Cache
* Spool files
* Application data

Important directory:

```text
/var/log
```

Cybersecurity analysts frequently investigate logs under `/var/log`.

---

### 6. `/tmp`

Temporary files.

Applications can use `/tmp` for temporary data.

Because temporary files can be created by many applications/users, security analysts should understand what is stored there.

---

### 7. `/usr`

Contains many user-space programs, libraries, documentation, and other shared resources.

Examples:

```text
/usr/bin
/usr/sbin
/usr/lib
```

---

### 8. `/bin`

Contains essential user commands.

Examples can include:

```text
ls
cp
mv
cat
```

On many modern distributions, `/bin` is integrated with `/usr/bin` through a filesystem layout known as **usr-merge**.

---

### 9. `/sbin`

Traditionally contains important system administration commands.

On modern systems, this may also be integrated into `/usr/sbin`.

---

### 10. `/dev`

Contains representations of devices.

Examples:

```text
/dev/sda
/dev/nvme0n1
```

Linux treats many hardware devices as files or file-like interfaces.

---

### 11. `/proc`

A virtual filesystem containing information about:

* Processes
* Kernel
* Memory
* Hardware-related runtime information

Example:

```bash
ls /proc
```

Process information can be found under directories such as:

```text
/proc/1234
```

where `1234` can be a process ID.

---

### 12. `/sys`

Provides information and interfaces related to the kernel and devices.

```text
/sys
```

---

### 13. `/boot`

Contains files required for booting the system.

Examples include:

* Linux kernel
* Bootloader-related files
* Initial RAM filesystem

---

### 14. `/opt`

Used by some applications for optional/additional software.

---

### 15. `/mnt`

Traditionally used as a temporary mount point for filesystems.

---

### 16. `/media`

Commonly used for automatically mounted removable media such as USB drives.

---

# C. Users and Groups

Linux is a **multi-user operating system**.

Multiple users can exist on the same machine, and Linux controls what each user can access.

## 1. User

A user account represents an identity in Linux.

Example:

```text
shafi
admin
student
```

Every user normally has:

* Username
* UID
* Primary group
* Home directory
* Login shell

---

# 2. Root User

The **root user** is the superuser.

Root has extensive privileges over the system.

Root can normally:

* Install software
* Modify system configuration
* Create/delete users
* Change permissions
* Start/stop services
* Access protected files

Root UID is normally:

```text
0
```

### Important security concept

Using root unnecessarily is dangerous because a mistake or malicious command can affect the entire system.

---

# 3. UID

UID means:

**User ID**

Linux internally identifies users using numeric IDs.

Example:

```text
shafi:x:1000:1000:...
```

Here `1000` may be the UID.

---

# 4. Groups

A group is a collection of users.

Groups make permission management easier.

Example:

```text
developers
sudo
docker
www-data
```

Instead of giving permissions individually to 20 users, an administrator can give permissions to a group.

---

# 5. Important Files

### `/etc/passwd`

Contains basic information about user accounts.

```bash
cat /etc/passwd
```

A typical entry has fields such as:

```text
username:x:UID:GID:comment:home:shell
```

---

### `/etc/group`

Contains group information.

```bash
cat /etc/group
```

---

### `/etc/shadow`

Contains password-related authentication data in protected form.

Normally it is readable only by privileged users.

```bash
sudo cat /etc/shadow
```

Do not modify these files casually.

---

# 6. Useful User Commands

### Check current user

```bash
whoami
```

Example output:

```text
shafi
```

### Show user identity and groups

```bash
id
```

### Show logged-in users

```bash
who
```

### Show more detailed login/activity information

```bash
w
```

### Change user

```bash
su username
```

### Run a command with elevated privileges

```bash
sudo command
```

Example:

```bash

```

# D. Linux Processes

## What is a Process?

A **process is a running instance of a program**.

For example, when you open Firefox:

```text
Firefox program
       ↓
Running Firefox
       ↓
Process
```

A process has a unique identifier called a:

**PID = Process ID**

---

## Program vs Process

This is an important interview/exam question.

### Program

A program is a file containing instructions.

### Process

A process is the running instance of that program.

Example:

```text
/usr/bin/firefox
```

is a program.

When Firefox runs:

```text
Firefox process
PID = 2450
```

is a process.

---

# 2. Process States

A Linux process can have different states.

Common states include:

* Running
* Sleeping
* Stopped
* Zombie

### Running

Currently executing or ready to execute.

### Sleeping

Waiting for an event/resource.

### Stopped

Execution has been suspended.

### Zombie

The process has finished execution, but its parent has not yet collected its exit status.

---

# 3. PID

PID means:

**Process ID**

Example:

```text
PID 1234
PID 2456
PID 3001
```

Every active process normally has a unique PID.

---

# 4. PPID

PPID means:

**Parent Process ID**

Processes can create other processes.

Example:

```text
Parent Process
      |
      +---- Child Process
```

The child process has a PPID pointing to its parent.

---

# 5. View Processes

### `ps`

```bash
ps
```

Shows processes associated with the current shell/session.

### `ps aux`

```bash
ps aux
```

Provides a broader process listing.

### `top`

```bash
top
```

Shows processes and resource usage dynamically.

### `htop`

```bash
htop
```

A more user-friendly interactive process viewer, if installed.

---

# 6. Kill a Process

If a process needs to be stopped, you can use:

```bash
kill PID
```

Example:

```bash
kill 2450
```

By default, `kill` sends a termination request using `SIGTERM`.

A stronger signal is:

```bash
kill -9 2450
```

`SIGKILL` immediately terminates the process and cannot be caught or handled by the process.

### Security note

Do not randomly kill system processes. It can cause applications or the operating system to malfunction.

---

# 7. Process Priority

Linux processes have a concept called **niceness**.

Commands:

```bash
nice
renice
```

These can influence CPU scheduling priority.

# E. System Services

## What is a System Service?

A system service is a background program that provides functionality to the operating system or other applications.

Examples:

* SSH server
* Web server
* DNS service
* Database server
* Logging service
* Network service

Examples of service software:

```text
sshd
nginx
apache2
cron
systemd-journald
```

---

# 1. systemd

Modern Linux distributions commonly use **systemd** as their system and service manager.

It can manage:

* System startup
* Services
* Processes
* Logging integration
* Mounts
* Timers
* Dependencies

---

# 2. `systemctl`

The main command used to interact with systemd services is:

```bash
systemctl
```

### Check service status

```bash
systemctl status ssh
```

### Start a service

```bash
sudo systemctl start ssh
```

### Stop a service

```bash
sudo systemctl stop ssh
```

### Restart a service

```bash
sudo systemctl restart ssh
```

### Enable service at boot

```bash
sudo systemctl enable ssh
```

### Disable service at boot

```bash
sudo systemctl disable ssh
```

### Check whether a service is running

```bash
systemctl is-active ssh
```

---

# 3. Active vs Enabled

This is an important exam question.

### Active

The service is currently running.

```text
Active = Running now
```

### Enabled

The service is configured to start automatically during boot.

```text
Enabled = Start automatically at boot
```

A service can therefore be:

```text
Active + Enabled
Active + Disabled
Inactive + Enabled
Inactive + Disabled
```

---

# 4. Why Services Matter in Cybersecurity

Security professionals need to know which services are running because every network-facing service can potentially increase the attack surface.

For example:

```text
Linux Server
     |
     +---- SSH
     |
     +---- Web Server
     |
     +---- Database
     |
     +---- DNS
```

An administrator should:

* Run only necessary services
* Keep services updated
* Configure authentication securely
* Monitor logs
* Restrict network access
* Disable unnecessary services

```bash

```

### Step 2 — Check system information

```bash

```

```bash
ls /
```

### Step 4 — Look at configuration

```bash

```

### Step 5 — Check users

```bash
cat /etc/passwd
```

### Step 6 — Check your groups

```bash

```

### Step 7 — Check processes

```bash
ps aux
```

### Step 8 — Check services

```bash
systemctl --type=service
```

### Step 9 — Check a particular service

```bash
systemctl status ssh
```

### Step 10 — Investigate logs

```bash
ls /var/log
```

This gives you a basic picture of the Linux system.

# Exam Questions and How to Answer

## Q1. What is Linux?

**Answer:**

> Linux is an open-source, Unix-like operating system kernel. It manages hardware resources such as CPU, memory, storage and network devices and provides services required by applications. Linux distributions such as Ubuntu, Debian, Fedora and Kali Linux package the kernel with other software to create complete operating systems.

---

## Q2. What is a Linux distribution?

> A Linux distribution is a complete operating system built around the Linux kernel. It includes system utilities, libraries, package managers and applications. Examples are Ubuntu, Debian, Fedora, RHEL and Kali Linux.

---

## Q3. What is `/etc`?

> `/etc` contains system-wide configuration files. Examples include user, network and service configuration files.

---

## Q4. Difference between `/` and `/root`?

> `/` is the root directory of the entire filesystem, while `/root` is the home directory of the root user.

---

## Q5. What is a process?

> A process is a running instance of a program. Each process normally has a unique Process ID or PID.

---

## Q6. What is PID?

> PID stands for Process ID. It is a numeric identifier assigned to a running process.

---

## Q7. What is a service?

> A service is a background program that provides a specific function to the operating system or other applications, such as SSH, web serving or logging.

---

## Q8. What is systemd?

> systemd is a system and service manager commonly used by modern Linux distributions. It manages system startup, services and other system resources.

---

## Q9. What is `systemctl`?

> `systemctl` is a command-line utility used to control and inspect systemd-managed services.

---

## Q10. What is the difference between a user and a group?

> A user represents an individual account, while a group is a collection of users used to manage permissions and access more efficiently.
