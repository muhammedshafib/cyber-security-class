# 4. Understand System Monitoring — Linux

**System monitoring** means checking the current condition and performance of a Linux system.

It helps you understand:

* Which programs are running
* How much CPU is being used
* How much RAM is available
* How much disk space is used
* Which services are running
* Whether the system is slow or overloaded
* What processes may be causing problems

For cybersecurity, system monitoring is especially important because unusual processes, network connections, CPU usage, or services can sometimes indicate suspicious activity.

---

# a. Process Monitoring

A **process** is a running program.

For example, when you open Firefox, Linux creates processes for Firefox.

### 1. `ps`

Shows currently running processes.

```bash
ps
```

For more detailed information:

```bash
ps aux
```

Example:

```text
USER       PID  %CPU %MEM    VSZ   RSS TTY      STAT START   TIME COMMAND
shafi     1234  2.1  1.5  ...   ...  pts/0    S+   ...      firefox
```

Important columns:

| Column    | Meaning                   |
| --------- | ------------------------- |
| `USER`    | User who owns the process |
| `PID`     | Process ID                |
| `%CPU`    | CPU usage                 |
| `%MEM`    | Memory usage              |
| `STAT`    | Process state             |
| `COMMAND` | Program/command           |

---

### 2. `top`

`top` provides **real-time process monitoring**.

```bash
top
```

You'll see CPU, RAM, load average, and running processes.

Useful keys inside `top`:

```text
q → Quit
P → Sort by CPU usage
M → Sort by memory usage
k → Kill a process
h → Help
```

For example, if one process is using 90% CPU, `top` can help you identify it.

---

### 3. `htop`

`htop` is an interactive alternative to `top`.

```bash
htop
```

If it isn't installed:

```bash
sudo apt update
sudo apt install htop
```

`htop` provides an easier visual interface for:

* CPU usage
* RAM usage
* Processes
* Process IDs
* Process priority

---

### 4. Find a process

```bash
pgrep firefox
```

Or:

```bash
pidof firefox
```

---

### 5. Find processes using `grep`

```bash
ps aux | grep firefox
```

This searches the process list for Firefox.

---

# Process IDs — PID

Every running process has a **PID (Process ID)**.

Example:

```text
Firefox → PID 2456
Terminal → PID 3012
```

You can use the PID to manage a process.

Check a specific process:

```bash
ps -p 2456
```

Detailed information:

```bash
ps -p 2456 -f
```

---

# Killing a Process

If a program becomes unresponsive, you can terminate it.

### Normal termination

```bash
kill 2456
```

If it doesn't stop:

```bash
kill -9 2456
```

`-9` sends a forceful termination signal.

⚠️ Use `kill -9` only when normal termination doesn't work.

# b. Memory Usage

**RAM (Random Access Memory)** temporarily stores data and programs currently being used.

If RAM becomes nearly full, the system may become slow.

---

## 1. `free`

Check memory usage:

```bash
free
```

Human-readable format:

```bash
free -h
```

Example:

```text
               total        used        free
Mem:            7.7Gi       3.2Gi       1.8Gi
Swap:           2.0Gi       0.0Gi       2.0Gi
```

### Important values

```text
total → Total RAM
used  → Currently used
free  → Completely unused
available → RAM available for new applications
swap → Disk space being used as virtual memory
```

For most practical monitoring, pay particular attention to **available memory**, not just `free`.

---

## 2. `/proc/meminfo`

Linux provides detailed memory information through `/proc`.

```bash
cat /proc/meminfo
```

For example:

```bash
cat /proc/meminfo | head
```

---

## 3. Monitor memory continuously

```bash
watch -n 2 free -h
```

This refreshes the memory information every 2 seconds.

Exit with:

```text
Ctrl + C
```

---

# c. Disk Utilization

Disk monitoring tells you how much storage space is being used.

---

## 1. `df`

Check filesystem disk usage:

```bash
df
```

Human-readable:

```bash
df -h
```

Example:

```text
Filesystem      Size  Used Avail Use% Mounted on
/dev/sda1       100G   65G   30G  69% /
```

Important columns:

| Column       | Meaning                              |
| ------------ | ------------------------------------ |
| `Size`       | Total filesystem size                |
| `Used`       | Used space                           |
| `Avail`      | Available space                      |
| `Use%`       | Percentage used                      |
| `Mounted on` | Location where filesystem is mounted |

---

## 2. Check a specific directory

```bash
df -h /
```

Check another mounted location:

```bash
df -h /home
```

---

# Disk Usage of Directories

### `du`

`du` means **disk usage**.

Check current directory:

```bash
du -h
```

Check a specific directory:

```bash
du -sh /home
```

Example:

```text
12G    /home
```

`-s` = summary
`-h` = human-readable

---

### Find large directories

```bash
du -h --max-depth=1 /home
```

This helps identify which directories are consuming storage.

---

## Find large files

One useful command is:

```bash
find /home -type f -size +500M
```

This searches `/home` for files larger than 500 MB.

---

# Disk and Storage Difference

Don't confuse:

```text
df → Filesystem/storage utilization
du → Files/directories consuming storage
```

Easy memory trick:

**DF = Disk Filesystem**

**DU = Disk Usage**

---

# d. Service Management

A **service** is a background program that provides a function to the system.

Examples:

* SSH server
* Web server
* Database server
* Network services
* Logging services

Modern Linux distributions commonly use **systemd** to manage services.

The main command is:

```bash
systemctl
```

---

## Check service status

For SSH:

```bash
systemctl status ssh
```

You may see:

```text
Active: active (running)
```

This means the service is currently running.

---

## Start a service

```bash
sudo systemctl start ssh
```

---

## Stop a service

```bash
sudo systemctl stop ssh
```

---

## Restart a service

```bash
sudo systemctl restart ssh
```

Restarting is often useful after changing a service's configuration.

---

## Reload configuration

Some services support:

```bash
sudo systemctl reload service_name
```

Reloading attempts to apply configuration changes without fully restarting the service.

---

## Enable service at boot

```bash
sudo systemctl enable ssh
```

This makes the service start automatically during boot.

---

## Disable service at boot

```bash
sudo systemctl disable ssh
```

---

## Check whether service is enabled

```bash
systemctl is-enabled ssh
```

---

## Check whether service is running

```bash
systemctl is-active ssh
```

---

# List Running Services

```bash
systemctl list-units --type=service --state=running
```

List all service units:

```bash
systemctl list-units --type=service
```

---

# View Service Logs

`journalctl` displays logs collected by systemd's journal.

For SSH:

```bash
sudo journalctl -u ssh
```

View recent entries:

```bash
sudo journalctl -u ssh -n 50
```

Follow new entries live:

```bash
sudo journalctl -u ssh -f
```

Press:

```text
Ctrl + C
```

to exit.

# e. Performance Observation

Performance monitoring means observing the overall health of the system.

The main resources are:

```text
CPU
RAM
Disk
Processes
Network
Services
```

---

## 1. CPU Load

Use:

```bash
uptime
```

Example:

```text
10:30:20 up 2 hours, 1 user, load average: 0.50, 0.70, 0.60
```

The three load-average numbers normally represent approximately:

```text
1 minute
5 minutes
15 minutes
```

Load average should be interpreted relative to the number of CPU cores. A load of `2` can be heavy on a 1-core system but modest on a 8-core system.

# 6. I/O Performance

For disk I/O statistics, `iostat` is useful.

```bash

```

Then:

```bash
iostat
```

More detailed:

```bash

```

This can help identify storage devices experiencing high utilization or latency.

# 7. Network Monitoring

Check network interfaces:

```bash

```

Show network statistics:

```bash

```

Check active connections:

```bash
ss -tuln
```

For more detailed connections:

```bash
ss -tunap
```

These commands are particularly useful for cybersecurity monitoring because unexpected listening ports or connections can deserve investigation.

# 🔍 Practical Monitoring Workflow

When your Linux system becomes slow, don't randomly kill processes. Investigate systematically.

### Step 1 — Check load

```bash
uptime
```

### Step 2 — Check CPU and processes

```bash
top
```

### Step 3 — Check RAM

```bash
free -h
```

### Step 4 — Check disk space

```bash
df -h
```

### Step 5 — Find large directories

```bash
du -h --max-depth=1 /home
```

### Step 6 — Check services

```bash
systemctl --type=service --state=running
```

### Step 7 — Check logs

```bash
sudo journalctl -p warning -b
```

### Step 8 — Check network connections

```bash
ss -tuln
```

# 🛡️ Cybersecurity Example

Suppose you notice that your Kali Linux machine suddenly becomes very slow.

You could investigate:

```bash
top
```

You discover:

```text
Process             CPU
unknown_process     95%
```

Find more information:

```bash
ps -fp PID
```

Then check its executable:

```bash
readlink -f /proc/PID/exe
```

You can also inspect its network connections:

```bash
sudo ss -tunap
```

And investigate relevant logs:

```bash
sudo journalctl
```

**Don't immediately assume that an unknown process is malware.** First determine what package/application created it, which user owns it, what it is doing, and whether it is expected.

## 🧠 Easy Way to Remember

| What you want to check | Command      |
| ---------------------- | ------------ |
| Running processes      | `ps aux`     |
| Live CPU/processes     | `top`        |
| Easy process monitor   | `htop`       |
| RAM                    | `free -h`    |
| Disk space             | `df -h`      |
| Directory size         | `du -sh`     |
| Services               | `systemctl`  |
| Logs                   | `journalctl` |
| CPU information        | `lscpu`      |
| System load            | `uptime`     |
| Network connections    | `ss`         |

### Core concept

**Process → CPU/RAM → Disk → Services → Logs → Network**

This is the basic Linux **system monitoring workflow** you should know before moving deeper into cybersecurity.
