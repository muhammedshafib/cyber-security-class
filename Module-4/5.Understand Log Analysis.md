# 5. Understand Log Analysis

**Log analysis** means reading and examining system-generated records called **logs** to understand what happened on a computer, server, application, or network.

In cybersecurity, logs are very important because they help us detect **attacks, unauthorized access, errors, suspicious activity, and system problems**.

---

## a. System Logs

### What are system logs?

System logs record events related to the **operating system**.

They can tell you:

* When the system started or shut down
* Hardware or driver problems
* Kernel events
* System errors
* Network changes
* Software crashes
* Security-related events

### Linux examples

Common locations:

```bash
/var/log/syslog
/var/log/messages
/var/log/kern.log
/var/log/dmesg
```

On systems using `systemd`, you can use:

```bash
journalctl
```

Show recent system logs:

```bash
journalctl
```

Show logs from the current boot:

```bash
journalctl -b
```

Show kernel messages:

```bash
journalctl -k
```

Show the latest 50 entries:

```bash
journalctl -n 50
```

Follow logs in real time:

```bash
journalctl -f
```

### Example

```text
Aug 19 09:10:22 kali kernel: eth0: link is up
Aug 19 09:11:05 kali kernel: USB device connected
Aug 19 09:12:14 kali systemd: Started Network Manager
```

These entries help you understand what the operating system is doing.

# b. Authentication Logs

### What are authentication logs?

Authentication logs record events related to **users logging in and accessing the system**.

They can show:

* Successful login
* Failed login
* SSH login
* `sudo` usage
* User authentication failures
* Account activity

On many Linux distributions, authentication information can be found in:

```bash
/var/log/auth.log
```

On some distributions:

```bash
/var/log/secure
```

Search for failed logins:

```bash
grep "Failed" /var/log/auth.log
```

Search for successful SSH logins:

```bash
grep "Accepted" /var/log/auth.log
```

Watch authentication events:

```bash
tail -f /var/log/auth.log
```

Using `journalctl`:

```bash
journalctl -u ssh
```

### Example

```text
Failed password for user admin from 192.168.1.50
Failed password for user admin from 192.168.1.50
Failed password for user admin from 192.168.1.50
Accepted password for user admin from 192.168.1.50
```

This could indicate repeated login attempts followed by a successful login.

**Important:** A failed login alone does not prove an attack. You need to examine the surrounding events and context.

# c. Service Logs

### What are service logs?

Services are background programs that perform tasks such as:

* SSH
* Web servers
* DNS
* Database servers
* Network services
* Docker
* Cron jobs

Each service may generate its own logs.

For example, SSH:

```bash
journalctl -u ssh
```

Follow SSH logs:

```bash
journalctl -u ssh -f
```

Show Nginx logs:

```bash
journalctl -u nginx
```

Apache logs are commonly located at:

```bash
/var/log/apache2/access.log
/var/log/apache2/error.log
```

Nginx commonly uses:

```bash
/var/log/nginx/access.log
/var/log/nginx/error.log
```

### Example web-server log

```text
192.168.1.20 - - [19/Aug/2026:09:20:15]
"GET /index.html HTTP/1.1" 200
```

This tells you:

* **IP:** `192.168.1.20`
* **Request:** `GET /index.html`
* **Status:** `200`
* **Meaning:** Request was successful

# d. Log Investigation

Log investigation means **examining logs systematically to find out what happened**.

A basic investigation process is:

### 1. Identify the event

Ask:

> What happened?

Example:

```text
Multiple failed SSH login attempts
```

### 2. Find the relevant log

For SSH:

```bash
/var/log/auth.log
```

or:

```bash
journalctl -u ssh
```

### 3. Search the logs

Use `grep`:

```bash
grep "Failed password" /var/log/auth.log
```

Search for a specific IP:

```bash
grep "192.168.1.50" /var/log/auth.log
```

### 4. Check the timestamp

Look at:

```text
Date
Time
Timezone
```

Timing is extremely important when investigating an incident.

### 5. Identify the user

Look for:

```text
username
UID
authentication method
```

### 6. Identify the source

Check:

```text
Source IP
Hostname
Process
Service
```

### 7. Correlate different logs

For example:

```text
09:10 → Failed SSH login
09:11 → Failed SSH login
09:12 → Successful SSH login
09:13 → sudo command executed
09:14 → New process started
```

Looking at these events together gives much more information than looking at one log entry.

### Useful commands

View a file:

```bash
cat /var/log/auth.log
```

View page by page:

```bash
less /var/log/auth.log
```

Search:

```bash
grep "error" /var/log/syslog
```

Search case-insensitively:

```bash
grep -i "error" /var/log/syslog
```

Show the last 100 lines:

```bash
tail -n 100 /var/log/syslog
```

Monitor new entries:

```bash
tail -f /var/log/syslog
```

Count matching entries:

```bash
grep -c "Failed password" /var/log/auth.log
```

# e. Security Indicators

Security indicators are **signs in logs that may indicate suspicious or malicious activity**.

### 1. Repeated failed logins

```text
Failed password
Failed password
Failed password
Failed password
```

Possible indicator:

**Brute-force login attempts**

---

### 2. Successful login after many failures

```text
Failed login
Failed login
Failed login
Successful login
```

This deserves investigation.

---

### 3. Login from an unusual location/IP

Example:

```text
User: admin
Source IP: 203.0.113.50
```

If the IP is unexpected, investigate it.

---

### 4. Unexpected privilege escalation

Example:

```text
sudo command executed
```

or unexpected root activity.

Investigate:

```bash
grep "sudo" /var/log/auth.log
```

---

### 5. Unknown users

Check users:

```bash
cat /etc/passwd
```

Check recent account-related changes using appropriate system/account logs.

---

### 6. Suspicious processes

Check running processes:

```bash
ps aux
```

or:

```bash
top
```

Look for:

* Unknown processes
* Unexpected programs
* High CPU usage
* Processes running as root

---

### 7. Service failures

Example:

```text
Failed to start service
Service stopped unexpectedly
```

Check:

```bash
journalctl -p err
```

# Important Log Analysis Commands

| Purpose                 | Command               |
| ----------------------- | --------------------- |
| View system journal     | `journalctl`          |
| Current boot logs       | `journalctl -b`       |
| Follow logs             | `journalctl -f`       |
| Kernel logs             | `journalctl -k`       |
| SSH logs                | `journalctl -u ssh`   |
| View file               | `cat file`            |
| Read large file         | `less file`           |
| Search text             | `grep "text" file`    |
| Case-insensitive search | `grep -i "text" file` |
| Last lines              | `tail file`           |
| Last 100 lines          | `tail -n 100 file`    |
| Live monitoring         | `tail -f file`        |
| Count matches           | `grep -c "text" file` |
| Running processes       | `ps aux`              |
| Process monitor         | `top`                 |

journalctl -n 50

```bash
sudo tail -n 50 /var/log/auth.log

sudo grep "Failed" /var/log/auth.log
```

### Step 4 — Search successful authentication

```bash
sudo grep "Accepted" /var/log/auth.log
```

```bash
sudo journalctl -u ssh
```

### Step 6 — Check system errors

```bash
sudo journalctl -p err
```

```bash
sudo journalctl -f
```

Press:

```text
Ctrl + C
```

to stop monitoring.

## 🧠 Easy way to remember

**System Logs →** What is the OS doing?

**Authentication Logs →** Who is logging in?

**Service Logs →** What are services doing?

**Log Investigation →** What happened and when?

**Security Indicators →** Does anything look suspicious?

### Cybersecurity mindset

When analyzing a suspicious event, think:

**WHO → WHAT → WHEN → WHERE → HOW → IMPACT**

Example:

> **Who:** `admin`
> **What:** SSH login
> **When:** 09:12
> **Where:** Source IP `192.168.1.50`
> **How:** Password authentication
> **Impact:** Check what happened after the login

This is the foundation of **SOC monitoring, incident response, threat hunting, and security investigations**.
