# 2. Understand Network Automation

Network automation means using Python to **communicate with network systems, perform repeatable checks, collect information, and generate results automatically**.

For cybersecurity learning, we'll start with safe examples that you can run against **your own computer, localhost, or systems you are authorized to test**.

The basic workflow is:

```text
Python
   ↓
Create network connection
   ↓
Communicate with a service
   ↓
Perform a check
   ↓
Collect result
   ↓
Generate report
```

---

# 2.1 Socket Programming Fundamentals

## What is a socket?

A **socket** is an endpoint used for network communication.

Think of it like a telephone:

```text
Computer A                         Computer B
    |                                  |
    |          Network                 |
    |--------------------------------->|
    |                                  |
 Socket                            Socket
```

Python provides socket programming through the built-in:

```python

```

### `socket.AF_INET`

Example:

```text

```

---

So:



# 2.2 Network Communication

A basic TCP connection can look like:

```python

sock = socket.socket(socket.AF_INET, socket.SOCK_STREAM)

sock.settimeout(5)

sock.connect(("example.com", 80))

print("Connection successful")

sock.close()
```

You previously asked about this code, so let's connect it to network automation.

---

## Step 1 — Create socket

```python

```

Create a TCP/IPv4 socket.

---

## Step 2 — Set timeout

```python

```

Tell Python:

The `5` means approximately **5 seconds**.

This is important in automation because a network operation can otherwise wait for a very long time.

```python

```

```text

     ↓

```

A network connection is commonly identified by:

```text
IP/hostname + port
```

For example:

```text
192.168.1.10:80
```

---

## Step 4 — Print result

```python

```

If `connect()` succeeds, Python reaches this line.

---

## Step 5 — Close

```python

```

Close the connection.

The basic mental model is:


# 2.3 Network Communication with `send()` and `recv()`

A socket can also send and receive data.

For learning, we can use a local TCP server and client.

### Server

```python
import socket

server = socket.socket(socket.AF_INET, socket.SOCK_STREAM)

server.bind(("127.0.0.1", 5000))
server.listen(1)

print("Waiting for connection...")

connection, address = server.accept()

data = connection.recv(1024)

print("Received:", data.decode())

connection.close()
server.close()
```

### Client

```python
import socket

client = socket.socket(socket.AF_INET, socket.SOCK_STREAM)

client.connect(("127.0.0.1", 5000))

client.send(b"Hello")

client.close()
```

Here:

```text
127.0.0.1
```

means **your own computer (localhost)**.

So this is a safe way to learn socket communication.

# 2.4 Service Interaction

A **network service** is a program that listens for connections and provides some functionality.

Examples include:

```text

SSH        → Remote administration
SMTP       → Email
```

Services normally listen on **ports**.

For example:

```text
HTTP
 ↓
Port 80
```

and:

```text
HTTPS
 ↓
Port 443
```

The important concept is:

```text
Service
   ↓
Listening socket
   ↓

   ↓

```

---

# Simple Service Check

Suppose you want to check whether a web service is reachable.

```python
import socket

host = "example.com"
port = 80

sock = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
sock.settimeout(5)

try:
    sock.connect((host, port))
    print("Service is reachable")

except socket.timeout:
    print("Connection timed out")

except ConnectionRefusedError:
    print("Connection refused")

finally:
    sock.close()
```

### Why `try`?

Network connections can fail.

For example:

```text
Connection refused
Timeout
DNS failure
Network unavailable
```

Instead of crashing, we handle the error.

# 2.5 Automated Checks

Now we're getting into **network automation**.

Instead of checking one service manually, Python can perform a predefined check.

For example:

```text
Check web service
      ↓
Check DNS service
      ↓
Check another authorized service
      ↓
Generate report
```

A simple function:

```python
import socket

def check_port(host, port):
    sock = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
    sock.settimeout(2)

    try:
        sock.connect((host, port))
        return True

    except (socket.timeout, ConnectionRefusedError):
        return False

    finally:
        sock.close()


if check_port("127.0.0.1", 80):
    print("Port 80 is reachable")
else:
    print("Port 80 is not reachable")
```

---

It accepts:


# 2.6 Basic Scanning Concepts

Now we reach **basic scanning**.

### What is a port?

Think of an IP address as a building:

```text
192.168.1.10
      ↓
   Building
```

Ports are like numbered doors:

```text
80
443
22
53
```

Different services can listen behind different ports.

For example:

```text
192.168.1.10:80
```

means:

```text
IP address → 192.168.1.10
Port       → 80
```

---

# What does a basic port check do?

A simple check attempts:

```text
Connect to IP + port
       ↓
Did connection succeed?
       ↓
YES → reachable/open
NO  → refused/timeout
```

Example:

```python
import socket

host = "127.0.0.1"

for port in [80, 443, 8080]:
    sock = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
    sock.settimeout(1)

    try:
        sock.connect((host, port))
        print(port, "is reachable")

    except (socket.timeout, ConnectionRefusedError):
        print(port, "is not reachable")

    finally:
        sock.close()
```

Because this uses:

```text
127.0.0.1
```

you're checking your **own computer**.

---

# What is happening in the loop?

```python
for port in [80, 443, 8080]:
```

Python checks:

```text
80
 ↓
443
 ↓
8080
```

For every port, it creates a socket and attempts a connection.

This is the beginning of automated scanning logic.

---

# Important: "Open" vs "Reachable"

A successful TCP connection generally tells you:

> Something accepted the TCP connection on that address and port.

It does **not automatically tell you**:

* the exact software,
* whether the software is secure,
* whether authentication is enabled,
* whether the service is vulnerable.

So don't assume:

```text
Port reachable
      =
System vulnerable
```

They are completely different things.

---

# 2.7 Basic Scanner Structure

Conceptually:

```text
          Target
            ↓
      Select port(s)
            ↓
      Create socket
            ↓
       Set timeout
            ↓
       Try connect
          ↙   ↘
       YES     NO
        ↓       ↓
    Report    Report
```

A simple authorized localhost checker:

```python
import socket

host = "127.0.0.1"
ports = [80, 443, 8080]

for port in ports:

    sock = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
    sock.settimeout(1)

    try:
        sock.connect((host, port))
        print(f"{host}:{port} reachable")

    except (socket.timeout, ConnectionRefusedError):
        print(f"{host}:{port} not reachable")

    finally:
        sock.close()
```

---

# 2.8 Why Timeouts Matter

Imagine you check 100 ports.

Without a timeout:

```text
Port 1
 ↓
Wait...
 ↓
Wait...
 ↓
Wait...
```

Your program could become very slow.

With:

```python
sock.settimeout(1)
```

each connection attempt has a limit.

This makes automation more predictable.

# 2.12 Security Considerations

Network automation must be used responsibly.

### Always know your target

Good:

```text
127.0.0.1
```

or a system you have explicit authorization to test.

Avoid scanning random public systems without permission.

### Don't assume results

A reachable port doesn't automatically mean a vulnerability.

### Use timeouts

Prevent scripts from hanging.

### Handle exceptions

Network operations fail regularly.

### Close sockets

Avoid leaving unnecessary connections open.

### Don't build destructive automation

Start with:

```text
Detect
 ↓
Report
 ↓
Human reviews
```

rather than:

```text
Detect
 ↓
Automatically attack/change/delete
```
