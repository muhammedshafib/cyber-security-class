# 2. Understand Encryption Fundamentals

Encryption is used to **protect data from unauthorized people**. It changes readable data into unreadable data and uses a **key** to control the process.

### Basic Encryption Flow

```text
Plaintext
    ↓
Encryption + Key
    ↓
Ciphertext
    ↓
Decryption + Key
    ↓
Plaintext
```

---

## 1. Plaintext

**Plaintext** is the original, readable information before encryption.

Example:

```text
Hello World
```

Other examples:

```text
Username: admin
Password: mypassword
Message: Meet me at 5 PM
```

So:

> **Plaintext = Original readable data**

---

## 2. Ciphertext

**Ciphertext** is the unreadable data produced after encryption.

Example:

```text
Plaintext:
Hello World

        ↓ Encryption

Ciphertext:
X7$kP9@2Lm...
```

A person who doesn't have the required key should not be able to understand the ciphertext.

> **Ciphertext = Encrypted/protected data**

---

## 3. Encryption Process

Encryption converts **plaintext → ciphertext**.

### Example

Suppose we have:

```text
Plaintext = "Hello"
```

We apply an encryption algorithm and a key:

```text
"Hello"
   ↓
Encryption Algorithm + Key
   ↓
"8F$k2@Lm..."
```

The important idea is:

```text
Plaintext + Key → Ciphertext
```

### Real-world examples

Encryption is used in:

* HTTPS websites
* Online banking
* Messaging applications
* VPNs
* Encrypted files
* Full-disk encryption

For example, when you use HTTPS:

```text
Your browser
     ↓
Encrypted communication
     ↓
Web server
```

Someone monitoring the network should not simply be able to read the protected application data.

---

## 4. Decryption Process

Decryption converts **ciphertext → plaintext**.

```text
Ciphertext
    ↓
Decryption + Correct Key
    ↓
Plaintext
```

Example:

```text
"8F$k2@Lm..."
       ↓
Decryption + Key
       ↓
"Hello"
```

So encryption and decryption work together:

```text
ENCRYPTION
Plaintext → Ciphertext

DECRYPTION
Ciphertext → Plaintext
```

### Simple example

Think about a locked box:

```text
📄 Message
   ↓
🔒 Lock
   ↓
📦 Locked box
   ↓
🔑 Correct key
   ↓
📄 Message
```

The **message** is plaintext.

The **locked box** represents ciphertext.

The **key** allows authorized access.

# 5. Key Management Concepts

A **cryptographic key** is information used by a cryptographic algorithm to encrypt or decrypt data.

Key management means **creating, storing, protecting, using, rotating, and eventually destroying cryptographic keys safely**.

### Important key-management concepts

#### 1. Key generation

Create a strong, unpredictable key.

```text
Generate → Strong Key
```

Keys should generally be generated using a secure random-number generator rather than something predictable like:

```text
123456
password
mykey
```

---

#### 2. Key storage

Keys must be protected.

Bad idea:

```python
key = "my-secret-key"
```

inside publicly shared source code.

Better approaches include:

* Secure key-management systems
* Hardware security modules (HSMs)
* Protected operating-system credential stores
* Properly configured secret-management systems

---

#### 3. Key protection

If an attacker obtains the encryption key, encrypted data may become accessible depending on the encryption design.

So:

```text
Encrypted Data + Stolen Key
          ↓
       Risk ⚠️
```

The key needs protection just as seriously as the data.

---

#### 4. Key rotation

**Key rotation** means replacing an old key with a new key according to a defined security policy.

```text
Old Key
   ↓
Rotate
   ↓
New Key
```

This can limit the impact if an old key is compromised.

---

#### 5. Key revocation

If a key is suspected to be compromised or should no longer be trusted, it may need to be **revoked**.

```text
Key compromised
       ↓
Revoke key
       ↓
Stop using it
```

---

#### 6. Key destruction

When a key is no longer needed, it should be securely removed according to the system's key-management policy.

---

# 🔑 Symmetric vs Asymmetric Encryption

This is an important encryption concept.

### Symmetric encryption

The **same key** is used for encryption and decryption.

```text
          Same Key
             🔑
              ↓
Plaintext → Encryption → Ciphertext
                         ↓
                      Decryption
                         ↓
                     Plaintext
```

Example:

**AES**

It is generally efficient for encrypting large amounts of data.

---

### Asymmetric encryption

Uses **two related keys**:

* Public key
* Private key

```text
Public Key  → Encryption
Private Key → Decryption
```

The public key can generally be shared, while the private key must be protected.

Examples include **RSA** and **ECC-based cryptography**.

# 🧠 Easy Revision

Remember these five terms:

| Term               | Simple meaning                        |
| ------------------ | ------------------------------------- |
| **Plaintext**      | Original readable data                |
| **Ciphertext**     | Encrypted unreadable data             |
| **Encryption**     | Plaintext → Ciphertext                |
| **Decryption**     | Ciphertext → Plaintext                |
| **Key management** | Protect and manage cryptographic keys |

### Mental Model

```text
       🔑 KEY
        ↓
PLAINTEXT
   ↓
ENCRYPTION
   ↓
CIPHERTEXT
   ↓
DECRYPTION + 🔑
   ↓
PLAINTEXT
```

**One important distinction:** encryption is mainly about **confidentiality**—keeping data secret. Hashing, which you asked about earlier, is mainly used for **integrity/verification** and is not a replacement for encryption.
