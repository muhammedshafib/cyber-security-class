# 3. Understand Symmetric Encryption

**Symmetric encryption** is a type of encryption where the **same secret key** is used to encrypt and decrypt data.

### Basic idea

```text
        🔑 Secret Key
             ↓
Plaintext → Encryption → Ciphertext
                         ↓
                    Decryption
                         ↓
                     Plaintext
             ↑
        🔑 Same Key
```

The main challenge is: **How can two parties securely get the same secret key?**

---

## 1. Shared-Key Encryption

In symmetric encryption, both sides use the **same secret key**.

For example:

```text
Alice                          Bob
  │                              │
  │       🔑 Secret Key          │
  └──────────────┬───────────────┘
                 │
Alice encrypts               Bob decrypts
     ↓                            ↓
Plaintext → Ciphertext → Plaintext
```

Alice and Bob must both have the correct key.

### Example

Suppose:

```text
Message = "Hello Bob"
Key = Secret123
```

Alice encrypts:

```text
"Hello Bob"
     ↓
Encryption + Secret Key
     ↓
Ciphertext
```

Bob uses the **same key** to decrypt it.

> **Symmetric = one shared secret key**

---

# 2. Encryption Workflows

A simple symmetric encryption workflow looks like this:

### Step 1 — Create plaintext

```text
My bank information
```

### Step 2 — Obtain a secret key

```text
🔑 Secret Key
```

### Step 3 — Encrypt

```text
Plaintext + Key
       ↓
   Encryption
       ↓
   Ciphertext
```

### Step 4 — Store or transmit ciphertext

```text
Ciphertext → Network / Storage
```

### Step 5 — Decrypt

The authorized recipient uses the appropriate key:

```text
Ciphertext + Key
       ↓
   Decryption
       ↓
   Plaintext
```

### Complete workflow

```text
📄 Plaintext
     ↓
🔑 Secret Key
     ↓
🔐 Encryption
     ↓
🔒 Ciphertext
     ↓
📡 Network / 💾 Storage
     ↓
🔐 Decryption + 🔑 Key
     ↓
📄 Plaintext
```

# 3. Key Protection

The encryption algorithm can be strong, but **poor key protection can still cause a security problem**.

Imagine:

```text
Strong encryption
       +
Stolen secret key
       ↓
     ⚠️ Risk
```

### Don't hard-code secrets

Avoid putting real secret keys directly into source code:

```python
key = "my-secret-key"
```

Especially if the code will be:

* Uploaded to GitHub
* Shared with others
* Stored in a public repository

### Better approaches

Use appropriate secret-management mechanisms, such as:

* Environment variables for simple development cases
* OS credential/secret stores
* Dedicated secret-management systems
* Hardware security modules (HSMs)
* Cloud key-management services

### Other key-management practices

**Key rotation**

```text
Old Key → Retire → New Key
```

**Key access control**

Only authorized applications/users should be able to access the key.

**Key backup**

Important keys may need secure backup so encrypted data isn't permanently lost.

**Key destruction**

When a key is no longer needed, it should be securely retired/destroyed according to the system's policy.

# 4. Practical Use Cases

Symmetric encryption is commonly used because it is generally **fast and efficient**.

### 1. File encryption

```text
Important file
      ↓
Symmetric encryption
      ↓
Encrypted file
```

Used to protect sensitive files.

---

### 2. Disk encryption

Full-disk or volume encryption protects data stored on a device.

For example:

```text
Laptop storage
      ↓
Encryption
      ↓
Protected data
```

If someone gets physical access to the storage, encryption can help prevent them from simply reading the stored data.

---

### 3. Network communication

Symmetric encryption is commonly used to protect the actual data exchanged during secure network sessions.

For example:

```text
Computer ←→ Secure connection ←→ Server
                🔐
```

Protocols such as TLS use symmetric cryptography for efficient data protection after the connection has established the necessary cryptographic keys.

---

### 4. Database protection

Sensitive information can sometimes be encrypted before being stored.

```text
Sensitive data
      ↓
Encryption
      ↓
Database
```

The exact design depends on what data needs protection and how the application needs to search/use it.

# 5. Security Considerations

There are several important things to remember.

### 🔑 1. Protect the key

The biggest rule:

> **Keep the secret key secret.**

If the key is exposed, the confidentiality provided by that key can be lost.

---

### 🔐 2. Use modern algorithms

Don't create your own encryption algorithm.

Use well-established algorithms such as:

* **AES**
* **ChaCha20**

For modern application encryption, authenticated-encryption modes such as **AES-GCM** or **ChaCha20-Poly1305** are commonly used because they provide confidentiality plus integrity/authentication.

---

### 🛡️ 3. Don't use encryption alone when integrity matters

Suppose an attacker changes encrypted data.

You also need a mechanism that can detect unauthorized modification.

Authenticated encryption helps:

```text
Plaintext
   ↓
Encryption
   ↓
Ciphertext + Authentication Tag
```

During decryption:

```text
Ciphertext + Tag
       ↓
Verification
       ↓
Valid? → Decrypt
Invalid? → Reject
```

---

### 🎲 4. Use proper nonces/IVs

Many symmetric encryption modes require a **nonce** or **IV (initialization vector)**.

These values help ensure that encrypting data does not produce unsafe repeated patterns.

**Never invent your own nonce/IV rules.** Follow the requirements of the cryptographic library and algorithm.

---

### 🚫 5. Don't use passwords directly as encryption keys

A password such as:

```text
mypassword123
```

is not normally suitable as a raw encryption key.

A proper **key-derivation function (KDF)** such as **Argon2id, scrypt, or PBKDF2** can be used when deriving keys from passwords, with appropriate parameters and salts.

# 🧠 Symmetric vs Hashing

Since you just learned hashing:

| Feature                  | Symmetric Encryption | Hashing                |
| ------------------------ | -------------------- | ---------------------- |
| Main purpose             | Confidentiality      | Integrity/verification |
| Reversible               | ✅ With key           | ❌ Normally             |
| Secret key               | ✅                    | ❌ Usually              |
| Example                  | AES                  | SHA-256                |
| Original data recovered? | ✅                    | ❌                      |

### Easy memory trick

**Symmetric encryption = 🔑 Same key**

```text
Encrypt → 🔑
Decrypt → 🔑
```

**Hashing = #️⃣ Fingerprint**

```text
Data → Hash
```
