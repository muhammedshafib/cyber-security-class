# 6. Understand Digital Signatures

A **digital signature** is a cryptographic method used to prove that a message or document came from a particular person or organization and that it was **not changed after signing**.

### Simple example

```text
Document
   ↓
Hash
   ↓
Digital Signature
   ↓
Send document + signature
```

The receiver can then verify the signature.

---

## 1. Identity Verification

Digital signatures help verify **who signed the data**.

A signer has:

* **Private key** → kept secret
* **Public key** → shared with others

```text
Private Key → Used to create signature
Public Key  → Used to verify signature
```

Example:

```text
Alice signs a document
        ↓
Private key
        ↓
Digital signature
        ↓
Bob verifies using Alice's public key
```

If the signature verifies correctly, it provides cryptographic evidence that the corresponding private key was used.

---

## 2. Non-Repudiation

**Non-repudiation** means providing evidence that can make it difficult for the signer to credibly deny having signed something.

Example:

```text
Alice
 ↓
Signs document with her private key
 ↓
Document + Digital Signature
 ↓
Bob
```

Bob can verify the signature using Alice's public key.

### Important

Digital signatures don't provide absolute proof of a person's real-world identity by themselves. The trustworthiness of the link between a public key and a person or organization depends on the **trust system** used.

---

## 3. Signature Workflow

A basic digital-signature workflow looks like this:

```text
             SIGNER

Document
   ↓
Hash function
   ↓
Hash value
   ↓
Private key
   ↓
Digital Signature
```

The signer sends:

```text
Document + Digital Signature
```

to the receiver.

### Example

```text
"Transfer ₹1000"
       ↓
      Hash
       ↓
   Hash value
       ↓
  Private key
       ↓
Digital signature
```

---

## 4. Verification Process

The receiver checks whether the signature is valid.

### Step 1

Receiver gets:

```text
Document + Digital Signature
```

### Step 2

The receiver calculates a hash of the received document.

```text
Document
   ↓
Hash
   ↓
New hash
```

### Step 3

The receiver uses the signer's **public key** to verify the digital signature.

### Step 4

The cryptographic results are checked.

If everything matches:

```text
✓ Signature valid
✓ Document has not been altered
```

If the document was changed:

```text
Document changed
       ↓
Hash changes
       ↓
Verification fails
```

---

## 5. Trust Models

A **trust model** explains how we decide that a public key actually belongs to the person or organization claiming it.

### A. Certificate Authority (CA)

A **Certificate Authority** issues digital certificates that connect a public key with an identity.

```text
Person / Website
       ↓
Public Key
       ↓
Certificate Authority
       ↓
Digital Certificate
```

This model is widely used on the web with **HTTPS/TLS**.

### B. Web of Trust

In a **Web of Trust**, users can verify and sign each other's public keys.

This approach is associated with technologies such as **OpenPGP**.

### C. Direct Trust

Sometimes you obtain a public key directly from a trusted source and verify its fingerprint yourself.

```text
Public Key
     ↓
Check fingerprint
     ↓
Confirm identity
     ↓
Trust key
```

# Simple Summary

| Topic                     | Simple meaning                                       |
| ------------------------- | ---------------------------------------------------- |
| **Identity verification** | Helps verify who signed the data                     |
| **Non-repudiation**       | Provides evidence associated with the signing action |
| **Signature workflow**    | Private key is used to create the signature          |
| **Verification process**  | Public key is used to verify the signature           |
| **Trust models**          | Explain how we trust a public key's identity         |

### Easy way to remember

```text
Private Key → SIGN
Public Key  → VERIFY

Digital Signature
       ↓
Identity + Integrity + Evidence of signing
```

**Important difference:**

> **Encryption protects confidentiality.**
> **Digital signatures provide authentication/integrity and evidence of signing.**
