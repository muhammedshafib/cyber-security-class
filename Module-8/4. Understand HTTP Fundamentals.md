# 4. Understand HTTP Fundamentals

**HTTP (HyperText Transfer Protocol)** is the protocol used for communication between a **client** and a **web server**.

When you open a website, your browser and the web server communicate using HTTP or HTTPS.

Think of it like a conversation:

```text
Browser (Client)
       ↓
   HTTP Request
       ↓
   Web Server
       ↓
   HTTP Response
       ↓
Browser (Client)
```

For cybersecurity, HTTP is extremely important because web applications, APIs, login systems, cookies, and many attacks operate through HTTP communication.

---

# 1. Requests

An **HTTP request** is a message sent by the client to the server.

For example, when you visit:

```text
https://example.com
```

your browser sends a request to the server.

A simplified request looks like:

```http
GET / HTTP/1.1
Host: example.com
User-Agent: Mozilla/5.0
Accept: text/html
```

### Main parts of a request

```text
GET / HTTP/1.1
│    │     │
│    │     └── HTTP version
│    └──────── Resource/path
└───────────── HTTP method
```

Then there are **headers**:

```http
Host: example.com
User-Agent: Mozilla/5.0
Accept: text/html
```

Sometimes a request also contains a **body**.

For example, when submitting a login form:

```http
POST /login HTTP/1.1
Host: example.com
Content-Type: application/x-www-form-urlencoded

username=shafi&password=example
```

The body contains the submitted data.

> In real applications, passwords should be sent over **HTTPS**, not unencrypted HTTP.

---

# 2. Responses

After receiving a request, the server sends an **HTTP response** back to the browser.

Example:

```http
HTTP/1.1 200 OK
Content-Type: text/html
Content-Length: 1250

<html>
    <body>
        <h1>Welcome</h1>
    </body>
</html>
```

A response contains:

```text
Status Code
     ↓
Headers
     ↓
Body
```

### Status line

```http
HTTP/1.1 200 OK
```

Here:

* `HTTP/1.1` → HTTP version
* `200` → Status code
* `OK` → Meaning of the status code

### Response body

The body contains the actual content returned by the server.

For example:

```html
<h1>Welcome to my website</h1>
```

It could also contain:

* HTML
* JSON
* CSS
* JavaScript
* Images
* Other data

---

# 3. HTTP Methods

HTTP methods tell the server **what the client wants to do**.

The most important methods are:

| Method    | Common purpose                                        |
| --------- | ----------------------------------------------------- |
| `GET`     | Retrieve data                                         |
| `POST`    | Send/create data                                      |
| `PUT`     | Replace/update data                                   |
| `PATCH`   | Partially update data                                 |
| `DELETE`  | Delete data                                           |
| `HEAD`    | Get response headers without the normal response body |
| `OPTIONS` | Ask what methods/options are supported                |

---

## GET

Used to retrieve information.

Example:

```http
GET /products HTTP/1.1
Host: example.com
```

Meaning:

> "Give me the products."

A GET request can have query parameters:

```text
/products?id=10
```

Here:

```text
/products → Path
?id=10    → Query parameter
```

---

## POST

Used to send data to the server.

Example:

```http
POST /login HTTP/1.1
Host: example.com
Content-Type: application/x-www-form-urlencoded

username=shafi&password=example
```

The data is placed in the request body.

POST is commonly used for:

* Login
* Registration
* Uploading data
* Creating resources
* Submitting forms

---

## PUT

Used to replace/update a resource.

Example:

```http
PUT /users/10 HTTP/1.1
```

It might send updated user information in the body.

---

## PATCH

Used when you want to update only part of a resource.

For example:

```http
PATCH /users/10 HTTP/1.1
```

The body might contain only:

```json
{
    "email": "new@example.com"
}
```

---

## DELETE

Used to request deletion of a resource.

```http
DELETE /users/10 HTTP/1.1
```

---

# 4. Status Codes

The server uses **status codes** to tell the client what happened with the request.

They are divided into five groups:

```text
1xx → Informational
2xx → Success
3xx → Redirection
4xx → Client error
5xx → Server error
```

---

## 1xx — Informational

Example:

```text
100 Continue
```

These indicate that the request is being processed or additional communication is expected.

---

## 2xx — Success

### 200 OK

The request was successful.

```text
GET /index.html
        ↓
200 OK
```

### 201 Created

A resource was successfully created.

Common with APIs after creating something.

### 204 No Content

The request succeeded, but there is no response body to return.

---

# 3xx — Redirection

### 301 Moved Permanently

The resource has permanently moved to another URL.

### 302 Found

The server is temporarily redirecting the client.

Example:

```text
http://example.com
       ↓
302
       ↓
https://example.com
```

---

# 4xx — Client Errors

These usually mean something is wrong with the request or the client's access.

### 400 Bad Request

The server cannot understand the request.

### 401 Unauthorized

Authentication is required or failed.

Example:

```text
Access protected page
        ↓
401
        ↓
Login required
```

### 403 Forbidden

The server understood the request but refuses access.

Important distinction:

```text
401 → Authentication issue
403 → Access is forbidden
```

### 404 Not Found

The requested resource could not be found.

```text
GET /abcxyz
      ↓
404 Not Found
```

### 405 Method Not Allowed

The server doesn't allow that HTTP method for the requested resource.

---

# 5xx — Server Errors

These indicate that something went wrong on the server side.

### 500 Internal Server Error

A general server-side error.

### 502 Bad Gateway

A server acting as a gateway/proxy received an invalid response from an upstream server.

### 503 Service Unavailable

The server is temporarily unable to handle the request.

---

# 5. HTTP Headers

**Headers** provide additional information about an HTTP request or response.

Think of headers as **metadata** about the communication.

Example request:

```http
GET /login HTTP/1.1
Host: example.com
User-Agent: Mozilla/5.0
Accept: text/html
Cookie: session=abc123
```

---

## Important Request Headers

### Host

Identifies the server/domain being requested.

```http
Host: example.com
```

### User-Agent

Provides information about the client/browser.

```http
User-Agent: Mozilla/5.0
```

### Accept

Tells the server what response formats the client can accept.

```http
Accept: text/html
```

### Content-Type

Specifies the format of data being sent.

Example:

```http
Content-Type: application/json
```

The body might be:

```json
{
    "username": "shafi"
}
```

### Cookie

Sends cookies to the server.

```http
Cookie: session=abc123
```

Cookies are commonly used for:

* Login sessions
* Preferences
* Tracking
* Authentication state

---

# Important Response Headers

### Content-Type

Tells the browser what type of content is being returned.

```http
Content-Type: text/html
```

or:

```http
Content-Type: application/json
```

### Content-Length

Specifies the size of the response body.

```http
Content-Length: 1250
```

### Set-Cookie

The server can ask the browser to store a cookie.

```http
Set-Cookie: session=abc123
```

### Location

Often used with redirects.

```http
Location: /login
```

### Cache-Control

Controls how a response can be cached.

```http
Cache-Control: no-store
```

### Content-Security-Policy

A security-related response header that can help restrict which resources a browser is allowed to load.

Example:

```http
Content-Security-Policy: default-src 'self'
```

# Complete HTTP Communication

Let's put everything together.

### Step 1 — Browser sends request

```http
GET /index.html HTTP/1.1
Host: example.com
User-Agent: Mozilla/5.0
Accept: text/html
```

### Step 2 — Server processes request

The server finds `index.html`.

### Step 3 — Server sends response

```http
HTTP/1.1 200 OK
Content-Type: text/html
Content-Length: 1200

<html>
    <body>
        <h1>Welcome</h1>
    </body>
</html>
```

### Step 4 — Browser displays the page

```text
Browser
   │
   │ GET /index.html
   ↓
Server
   │
   │ 200 OK + HTML
   ↓
Browser
   │
   ↓
Web page
```

# HTTP vs HTTPS

This is especially important for cybersecurity.

### HTTP

```text
Browser
   ↓
HTTP
   ↓
Server
```

HTTP does not provide encryption by itself.

### HTTPS

```text
Browser
   ↓
TLS encryption
   ↓
HTTPS
   ↓
Server
```

HTTPS uses **TLS (Transport Layer Security)** to protect HTTP communication in transit.

This helps protect against attackers reading or modifying traffic while it travels across an untrusted network.

# Practical Cybersecurity Exercise

Since you're learning cybersecurity, practice inspecting HTTP traffic using **Browser Developer Tools**.

### Step 1

Open Chrome.

### Step 2

Press:

```text
F12
```

or:

```text
Ctrl + Shift + I
```

### Step 3

Open the:

```text
Network
```

tab.

### Step 4

Visit a website you are authorized to inspect.

### Step 5

Click one of the requests.

You'll see information such as:

```text
Request URL
Request Method
Status Code
Remote Address
Request Headers
Response Headers
Request Payload
Response
Cookies
```

For example:

```text
Request Method: GET
Status Code: 200
Content-Type: text/html
```

This is one of the best ways to connect the theory to real web traffic.

# Security Perspective

As a cybersecurity student, remember this flow:

```text
                 HTTP
                  │
        ┌─────────┴─────────┐
        ↓                   ↓
     Request              Response
        │                   │
   ┌────┴────┐         ┌────┴────┐
   │         │         │         │
Method    Headers   Status    Headers
   │                   │
   └──── Body          └──── Body
```

Understanding these five topics—**requests, responses, methods, status codes, and headers**—will give you the foundation for later topics such as **Burp Suite, cookies, sessions, authentication, APIs, HTTPS/TLS, web vulnerabilities, and HTTP traffic analysis**.
