# 4. Understand HTTP Fundamentals

HTTP is one of the **most important concepts in web development and web security**.

When you open a website, your browser and the web server communicate using **HTTP** or **HTTPS**.

Simple idea:

```text
Browser                         Web Server
   │                                │
   │────── HTTP Request ───────────>│
   │                                │
   │<───── HTTP Response ───────────│
   │                                │
```

Think of it like:

> **Request = What the client asks for**
> **Response = What the server sends back**

---

# 1. HTTP Requests

An **HTTP request** is a message sent by a client to a server.

The client is usually:

* Browser
* Mobile application
* Python program
* JavaScript application
* API client

For example, when you type:

```text
https://example.com/login
```

your browser sends a request to the server.

### Basic request

```http
GET /login HTTP/1.1
Host: example.com
```

Let's understand each part.

### `GET`

This is the **HTTP method**.

It tells the server:

> "I want to get/read something."

### `/login`

This is the **path** or resource being requested.

### `HTTP/1.1`

This tells the server which HTTP version is being used.

### `Host`

This is an HTTP header.

It tells the server which website/host you want.

---

## HTTP Request Structure

A request generally contains:

```text
Request Line
     ↓
Headers
     ↓
Blank Line
     ↓
Body
```

Example:

```http
POST /login HTTP/1.1
Host: example.com
Content-Type: application/json

{
    "username": "shafi",
    "password": "12345"
}
```

Here:

### Request line

```http
POST /login HTTP/1.1
```

### Headers

```http
Host: example.com
Content-Type: application/json
```

### Body

```json
{
    "username": "shafi",
    "password": "12345"
}
```

The body contains data being sent to the server.

---

# 2. HTTP Responses

After receiving the request, the server sends an **HTTP response**.

Example:

```http
HTTP/1.1 200 OK
Content-Type: text/html

<html>
    <body>
        Login successful
    </body>
</html>
```

Think:

```text
Browser
   │
   │ Request
   ↓
Server
   │
   │ Response
   ↓
Browser
```

---

## Response Structure

An HTTP response generally contains:

```text
Status Line
     ↓
Headers
     ↓
Blank Line
     ↓
Body
```

Example:

```http
HTTP/1.1 200 OK
Content-Type: text/html
Content-Length: 25

<html>...</html>
```

### Status line

```http
HTTP/1.1 200 OK
```

### Headers

```http
Content-Type: text/html
Content-Length: 25
```

### Body

```html
<html>...</html>
```

The body contains the actual content/data returned by the server.

---

# 3. HTTP Methods

HTTP methods tell the server **what action the client wants to perform**.

The most important ones are:

| Method    | Simple meaning      | Common use                   |
| --------- | ------------------- | ---------------------------- |
| `GET`     | Get data            | Open webpage / retrieve data |
| `POST`    | Send data           | Login / create data          |
| `PUT`     | Replace/update data | Update a resource            |
| `PATCH`   | Partially update    | Change one field             |
| `DELETE`  | Delete data         | Remove a resource            |
| `HEAD`    | Get headers only    | Check resource information   |
| `OPTIONS` | Ask what is allowed | Discover supported methods   |

---

## GET

Used to retrieve information.

Example:

```http
GET /users HTTP/1.1
Host: example.com
```

Meaning:

> "Give me the users."

Usually, GET does not contain a request body.

---

## POST

Used to send data to the server.

For example, login:

```http
POST /login HTTP/1.1
Host: example.com
Content-Type: application/x-www-form-urlencoded

username=shafi&password=12345
```

Meaning:

> "Here is some data. Process it."

POST is commonly used for:

* Login
* Registration
* Form submission
* Creating resources
* Uploading data

---

## PUT

Usually means:

> "Replace/update this resource."

Example:

```http
PUT /users/10 HTTP/1.1
```

You might send:

```json
{
    "name": "Shafi",
    "email": "shafi@example.com"
}
```

---

## PATCH

PATCH is generally used for a **partial update**.

For example, you only want to change the name:

```http
PATCH /users/10 HTTP/1.1
```

```json
{
    "name": "Muhammed Shafi"
}
```

---

## DELETE

Used to remove a resource.

```http
DELETE /users/10 HTTP/1.1
```

Meaning:

> "Delete user 10."

---

# 4. HTTP Status Codes

When the server responds, it includes a **status code**.

Example:

```http
HTTP/1.1 200 OK
```

The number tells you what happened.

There are five major groups:

```text
1xx → Informational
2xx → Success
3xx → Redirection
4xx → Client error
5xx → Server error
```

---

## 1xx — Informational

Means:

> "The request has been received / processing continues."

Example:

```text
100 Continue
```

These are less commonly encountered during basic web development.

---

# 2xx — Success

Means:

> "The request was successfully processed."

### 200 OK

Most common success response.

```http
HTTP/1.1 200 OK
```

Meaning:

> Request succeeded.

---

### 201 Created

Used when something has been successfully created.

Example:

```http
POST /users
```

Response:

```text
201 Created
```

Meaning:

> A new user/resource was created.

---

### 204 No Content

Request succeeded, but there is no response body.

---

# 3xx — Redirection

Means:

> "You need to go somewhere else / use another location."

### 301 Moved Permanently

The resource has permanently moved.

### 302 Found

A temporary redirect.

### 304 Not Modified

The cached version can be used because the resource hasn't changed according to the relevant caching conditions.

Example:

```text
Browser → Server
         "Has this changed?"

Server → Browser
         "304 Not Modified"
```

---

# 4xx — Client Errors

Means there is a problem with the request from the client side.

### 400 Bad Request

The server cannot understand/process the request.

Example:

```text
400 Bad Request
```

Possible reason:

```text
Invalid JSON
Missing required parameter
Malformed request
```

---

### 401 Unauthorized

The request requires authentication.

For example:

```text
GET /profile
```

Server:

```text
401 Unauthorized
```

Meaning:

> "You need to authenticate."

---

### 403 Forbidden

The server understood the request but refuses to allow it.

Simple distinction:

```text
401 → Authentication is required/failed
403 → Access is forbidden
```

---

### 404 Not Found

The requested resource doesn't exist at that location.

Example:

```text
GET /abcxyz
```

Server:

```text
404 Not Found
```

---

### 405 Method Not Allowed

The resource exists, but that HTTP method isn't allowed for it.

Example:

```text
DELETE /articles/10
```

Server might respond:

```text
405 Method Not Allowed
```

---

# 5xx — Server Errors

Means something went wrong on the server side.

### 500 Internal Server Error

A general server-side error.

```text
500 Internal Server Error
```

---

### 502 Bad Gateway

A server acting as a gateway/proxy received an invalid response from an upstream server.

---

### 503 Service Unavailable

The server is temporarily unable to handle the request.

Possible reasons:

* Server overloaded
* Maintenance
* Temporary service problem

---

# Easy Status Code Memory Trick

Remember:

```text
1xx → Information
2xx → Success
3xx → Redirect
4xx → Client problem
5xx → Server problem
```

And remember these common codes:

```text
200 → OK
201 → Created
301 → Permanent redirect
302 → Temporary redirect
304 → Not Modified
400 → Bad Request
401 → Authentication required
403 → Forbidden
404 → Not Found
405 → Method Not Allowed
500 → Server Error
502 → Bad Gateway
503 → Service Unavailable
```

# 5. HTTP Headers

Headers provide **additional information about the request or response**.

Think of headers as **metadata**.

Example:

```http
GET /login HTTP/1.1
Host: example.com
User-Agent: Chrome
Accept: text/html
```

Here:

```text
Host
User-Agent
Accept
```

are headers.

---

## Request Headers

Sent from the client to the server.

Example:

```http
GET /login HTTP/1.1
Host: example.com
User-Agent: Mozilla/5.0
Accept: text/html
Accept-Language: en-US
```

### Host

Specifies the server/host being requested.

```http
Host: example.com
```

---

### User-Agent

Provides information about the client software.

Example:

```http
User-Agent: Mozilla/5.0 ...
```

It can help the server identify the browser/client.

---

### Accept

Tells the server what response formats the client can accept.

```http
Accept: text/html
```

Another example:

```http
Accept: application/json
```

---

### Content-Type

Tells the receiver what type of data is in the body.

Example:

```http
Content-Type: application/json
```

Then the body could be:

```json
{
    "username": "shafi"
}
```

Another example:

```http
Content-Type: application/x-www-form-urlencoded
```

---

### Authorization

Used to send authentication credentials/token information.

Example:

```http
Authorization: Bearer <token>
```

You will see this frequently when working with APIs.

---

### Cookie

Sends cookies from the browser to the server.

Example:

```http
Cookie: session_id=abc123
```

Cookies are commonly used for things such as sessions and preferences.

---

# Response Headers

These are sent from the server to the client.

Example:

```http
HTTP/1.1 200 OK
Content-Type: text/html
Content-Length: 1250
Set-Cookie: session_id=abc123
```

### Content-Type

Tells the browser what kind of content it received.

```http
Content-Type: text/html
```

means:

> "The response contains HTML."

For JSON:

```http
Content-Type: application/json
```

---

### Content-Length

Specifies the size of the response body.

```http
Content-Length: 1250
```

---

### Set-Cookie

Server asks the browser to store/update a cookie.

```http
Set-Cookie: session_id=abc123
```

---

### Location

Often used with redirects.

Example:

```http
HTTP/1.1 301 Moved Permanently
Location: https://example.com/new-page
```

It tells the client where the resource has moved.

---

# Putting Everything Together

Imagine you open a login page.

### Step 1 — Browser sends request

```http
GET /login HTTP/1.1
Host: example.com
User-Agent: Chrome
Accept: text/html
```

### Step 2 — Server responds

```http
HTTP/1.1 200 OK
Content-Type: text/html

<html>
    <body>
        Login Page
    </body>
</html>
```

Then you submit the login form.

### Step 3 — Browser sends POST request

```http
POST /login HTTP/1.1
Host: example.com
Content-Type: application/x-www-form-urlencoded

username=shafi&password=******
```

### Step 4 — Server processes it

If successful:

```http
HTTP/1.1 200 OK
Content-Type: text/html
```

If authentication fails, the application might return an error response such as:

```text
401 Unauthorized
```

# HTTP in One Diagram

```text
                    HTTP
                     │
          ┌──────────┴──────────┐
          │                     │
       REQUEST               RESPONSE
          │                     │
    ┌─────┼─────┐         ┌─────┼─────┐
    │     │     │         │     │     │
 Method  Headers Body   Status Headers Body
    │                       │
    │                       │
 GET/POST/etc.          200/404/etc.
```

### The key idea to remember

```text
REQUEST
↓
Method + URL/Path + Headers + Body

             ↓

SERVER

             ↓

RESPONSE
↓
Status Code + Headers + Body
```

For **web development and cybersecurity**, these five areas are fundamental because when you use browser Developer Tools, Burp Suite, Wireshark, APIs, or Python HTTP libraries, you'll constantly see **requests, responses, methods, status codes, and headers**.
