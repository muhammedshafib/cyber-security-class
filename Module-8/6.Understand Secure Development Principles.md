# Task 6 — Understand Secure Development Principles

## Objective

Understand the basic principles used to develop secure web applications and reduce common security risks.

## Topics Covered

### 1. Input Validation

Input validation means checking user-provided data before using it.

Important points:

* Never trust user input.
* Validate data on the backend.
* Check type, length, format, and allowed values.
* Use allowlists where appropriate.
* Use parameterized queries to prevent SQL injection.

### 2. Output Handling

Output handling means safely processing data before displaying or sending it.

Important points:

* Prevent Cross-Site Scripting (XSS).
* Use proper output encoding.
* Use `textContent` instead of unsafe `innerHTML` when displaying plain user data.
* Handle data according to its output context.
* Use Content Security Policy (CSP) as an additional security layer.

### 3. Authentication Awareness

Authentication verifies the identity of a user.

Important practices:

* Never store passwords in plain text.
* Use secure password hashing such as Argon2id, bcrypt, or scrypt.
* Use HTTPS.
* Use MFA when appropriate.
* Protect against brute-force attacks with rate limiting.
* Use secure password-reset mechanisms.
* Protect user sessions.

### 4. Authorization Awareness

Authorization determines what an authenticated user is allowed to do.

Important points:

* Always check permissions on the backend.
* Follow the principle of least privilege.
* Prevent users from accessing other users' data.
* Do not rely only on hiding buttons in the frontend.
* Check authorization for sensitive actions.

### 5. Secure Coding Mindset

Security should be considered throughout the development process.

Important practices:

* Never trust external input.
* Think about how a feature could be misused.
* Avoid hard-coding passwords, API keys, and secrets.
* Use safe error handling.
* Keep dependencies updated.
* Do not expose sensitive information in logs.
* Use secure defaults.
* Apply defense in depth.
* Test applications for security weaknesses.

## Key Security Principle

> **Never trust user input, always verify permissions, protect sensitive data, and think about security while developing the application.**

## Summary

Secure development is not a single step. It is a continuous process that includes:

**Validate → Authenticate → Authorize → Process Safely → Protect Data → Handle Output Safely → Monitor → Test**
