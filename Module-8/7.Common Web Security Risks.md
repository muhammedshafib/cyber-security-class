# Task 7 — Common Web Security Risks

## Objective

Understand common web security risks and learn basic methods to prevent them while developing web applications.

---

## 1. Injection Attacks

**Injection** happens when untrusted user input is interpreted as a command or code.

### Common examples

* SQL Injection
* Command Injection
* LDAP Injection
* Cross-Site Scripting (XSS)

### Example

Unsafe SQL:

```python
query = "SELECT * FROM users WHERE username='" + username + "'"
```

A safer approach is to use **parameterized queries**.

### Prevention

* Validate user input
* Use parameterized queries
* Safely handle output
* Avoid directly passing user input to commands
* Follow the principle of least privilege

---

## 2. Broken Authentication

**Broken authentication** means weaknesses in the authentication system allow attackers to bypass login or compromise user accounts.

### Common problems

* Weak passwords
* Unlimited login attempts
* Poor password reset mechanisms
* Authentication bypass
* Insecure session management
* No multi-factor authentication (MFA)
* Account enumeration

### Prevention

* Use strong password policies
* Store passwords using secure password hashing such as Argon2id, bcrypt, or scrypt
* Use HTTPS
* Implement rate limiting
* Use MFA where appropriate
* Secure sessions and cookies
* Regenerate session identifiers after authentication
* Properly invalidate sessions during logout

---

## 3. Sensitive Data Exposure

**Sensitive data exposure** occurs when private or important information is exposed to unauthorized people.

### Examples

* Passwords
* API keys
* Session tokens
* Personal information
* Financial information
* Private files

### Common causes

* Plaintext passwords
* Missing HTTPS
* Sensitive data in URLs
* Secrets in source code
* Sensitive information in logs
* Excessive API responses
* Poor access control

### Prevention

* Use HTTPS/TLS
* Hash passwords securely
* Encrypt sensitive data when appropriate
* Protect secrets
* Avoid sensitive information in URLs and logs
* Apply proper authorization
* Return only necessary data
* Secure backups

---

## 4. Security Misconfiguration

**Security misconfiguration** occurs when an application, server, or environment is configured insecurely.

### Examples

* Default passwords
* Debug mode enabled in production
* Unnecessary services
* Unnecessary exposed ports
* Weak permissions
* Publicly accessible sensitive files
* Incorrect CORS configuration
* Outdated software
* Detailed error messages

### Prevention

* Change default credentials
* Disable debug mode in production
* Disable unnecessary services
* Restrict unnecessary network exposure
* Use least-privilege permissions
* Protect sensitive files
* Configure security headers
* Keep software and dependencies updated
* Use safe error messages

---

## 5. OWASP Awareness

**OWASP** stands for **Open Worldwide Application Security Project**.

OWASP provides security guidance, tools, standards, and educational resources for application security.

### OWASP Top 10

The OWASP Top 10 is a well-known list of important categories of web application security risks.

Important areas include:

* Broken Access Control
* Cryptographic Failures
* Injection
* Insecure Design
* Security Misconfiguration
* Vulnerable and Outdated Components
* Identification and Authentication Failures
* Software and Data Integrity Failures
* Security Logging and Monitoring Failures
* Server-Side Request Forgery (SSRF)

The exact categories can change between OWASP Top 10 editions, so the current edition should be checked when using it as a formal security reference.

## Security Mindset

When developing a web application, always ask:

```text
Can the user provide malicious input?
        ↓
Can authentication be bypassed?
        ↓
Can one user access another user's data?
        ↓
Is sensitive data protected?
        ↓
Are permissions correct?
        ↓
Are security settings configured correctly?
        ↓
Are dependencies updated?
        ↓
Are important security events logged?
```

## Summary

| Risk                      | Main Problem                           | Basic Protection                            |
| ------------------------- | -------------------------------------- | ------------------------------------------- |
| Injection                 | Input becomes unintended commands/code | Validation + parameterized queries          |
| Broken Authentication     | Accounts can be compromised            | Secure authentication + MFA + rate limiting |
| Sensitive Data Exposure   | Private data is revealed               | HTTPS + hashing/encryption + access control |
| Security Misconfiguration | Unsafe settings                        | Secure configuration + updates              |
| OWASP Awareness           | Lack of security knowledge             | Follow security guidance and best practices |

### Key Principle

> **Never trust user input, protect sensitive data, verify identity, check permissions, configure systems securely, and follow secure development practices.**
