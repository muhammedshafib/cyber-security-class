# Task 8 — Security Logging & Monitoring

## Objective

Understand how applications record events, how security activity is monitored, and how logs can help detect and investigate security incidents.

---

## 1. Application Logs

**Application logs** are records of events that happen inside an application.

They can record:

* User login
* User logout
* File uploads
* API requests
* Database operations
* Application errors
* Important application activities

### Example

```text
2026-10-06 10:30:15
INFO
User login successful
user_id=102
```

### Common log levels

| Level    | Meaning                                        |
| -------- | ---------------------------------------------- |
| DEBUG    | Detailed information useful during development |
| INFO     | Normal application activity                    |
| WARNING  | Something unusual happened                     |
| ERROR    | Something failed                               |
| CRITICAL | Serious problem                                |

### Importance

Application logs help with:

* Debugging
* Troubleshooting
* Security investigations
* Monitoring application behavior

---

## 2. Access Logs

**Access logs** record requests made to a web server or application.

### Example

```text
192.168.1.10
GET
/products
200
```

This means:

```text
IP Address → 192.168.1.10
Method     → GET
Resource   → /products
Status     → 200
```

### Access logs can help identify:

* Repeated failed requests
* Unusual traffic
* Brute-force attempts
* Suspicious requests
* Scanning activity
* Unexpected access to resources

### Example

```text
192.168.1.10 POST /login 401
```

The `401` response indicates that authentication was not successful for that request.

---

## 3. Error Logs

**Error logs** record problems or failures in an application or system.

### Example

```text
2026-10-06 11:20:10
ERROR
Database connection failed
```

Other examples:

```text
File upload failed
API request failed
Database query failed
Unexpected application error
```

### Why error logs are important

Error logs help developers and security teams:

* Find application problems
* Troubleshoot failures
* Detect unusual activity
* Investigate security incidents

### Security consideration

Do not expose sensitive technical information to normal users.

Instead of:

```text
Database: customer_db
Server: 192.168.1.20
File: /var/www/app/login.py
```

show the user a safer message:

```text
Something went wrong. Please try again later.
```

Detailed information can be recorded securely for authorized personnel.

---

## 4. Audit Trails

An **audit trail** records important actions performed by users or systems.

The basic idea is:

> **Who did what, when, and to which resource?**

### Example

```text
Time: 10:30
User: Admin
Action: Deleted user
Target: User ID 205
```

Another example:

```text
Time: 11:15
User: Admin
Action: Changed user role
Target: User ID 205
Old Role: User
New Role: Admin
```

### Important audit events

* Account creation
* Account deletion
* Permission changes
* Role changes
* Password changes
* Sensitive data access
* Important configuration changes
* Administrative actions

### Application logs vs Audit trails

**Application log:**

```text
User opened dashboard
API request received
Database operation completed
```

**Audit trail:**

```text
Admin deleted account
Admin changed permissions
User changed email address
```

Audit trails are especially useful for **accountability and investigations**.

---

## 5. Security Visibility

**Security visibility** means having enough information to understand what is happening inside an application, server, or network.

Without security visibility:

```text
Attack happens
     ↓
Nobody notices
```

With security visibility:

```text
Attack happens
     ↓
Logs record activity
     ↓
Monitoring detects unusual behavior
     ↓
Alert generated
     ↓
Security team investigates
```

---

# Logging vs Monitoring

These two concepts are related but different.

### Logging

**Records what happened.**

```text
Failed login from 10.0.0.5
```

### Monitoring

**Watches activity and looks for unusual behavior.**

```text
100 failed logins in 1 minute
        ↓
Monitoring detects unusual activity
        ↓
Alert
```

### Easy way to remember

> **Logging = Record it**
> **Monitoring = Watch it**

# What Should Be Logged?

### Authentication events

```text
Login success
Login failure
Logout
Password change
Password reset
MFA failure
```

### Authorization events

```text
Permission denied
Role changed
Access to sensitive resource
```

### Important actions

```text
Account created
Account deleted
Sensitive data modified
Admin settings changed
```

### System/application events

```text
Application started
Application stopped
Database failure
Configuration change
```

---

# What Should NOT Be Logged?

Sensitive information should not normally be stored in logs.

❌ Avoid logging:

```text
Passwords
Credit card numbers
Session tokens
API keys
Encryption keys
Authentication secrets
```

### Bad

```text
username=john
password=Hello123
```

### Better

```text
username=john
login=failed
```

Logs themselves must be protected because they can contain sensitive information.

# Example: Detecting Suspicious Activity

Suppose the logs contain:

```text
Failed login from 10.0.0.5
Failed login from 10.0.0.5
Failed login from 10.0.0.5
Failed login from 10.0.0.5
Failed login from 10.0.0.5
```

A monitoring system could identify:

```text
5 failed attempts
       ↓
Same source
       ↓
Short period
       ↓
Possible brute-force activity
       ↓
Generate alert
```

This is an important connection between **security logging, monitoring, and security automation**.

| Topic               | Simple Meaning                              |
| ------------------- | ------------------------------------------- |
| Application Logs    | Record application events                   |
| Access Logs         | Record web requests                         |
| Error Logs          | Record failures and errors                  |
| Audit Trails        | Record important actions for accountability |
| Security Visibility | Ability to understand security activity     |
| Logging             | Record events                               |
| Monitoring          | Watch events for problems                   |
| Alerting            | Notify when suspicious activity is detected |

---

# Security Logging Best Practices

1. Log important security events.
2. Include useful timestamps.
3. Protect log files from unauthorized access.
4. Do not log passwords or secrets.
5. Monitor logs for suspicious activity.
6. Create alerts for important security events.
7. Keep logs for an appropriate period.
8. Protect logs from unauthorized modification.
9. Synchronize system time where appropriate.
10. Regularly review and improve logging.

## Key Principle

> **If you cannot see what is happening in your system, it becomes much harder to detect, investigate, and respond to security incidents.**

Security logging and monitoring provides the **visibility needed to understand what is happening and identify suspicious activity.**
