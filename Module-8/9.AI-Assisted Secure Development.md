# Task 9 — AI-Assisted Secure Development

## Objective

Understand how AI can assist developers in writing, reviewing, and improving secure code, while learning why AI-generated security recommendations must always be reviewed and validated.

---

# 1. Use AI For

AI can be used as a **development assistant** to help identify security problems, suggest improvements, and discuss secure design.

However:

> **AI is an assistant, not the final security authority.**

Developers must review and verify AI-generated suggestions.

---

## 1.1 Code Reviews

AI can help review code and identify:

* Bugs
* Poor coding practices
* Unnecessary code
* Possible security weaknesses
* Error-handling problems
* Performance issues

### Example

You can give AI code like:

```python
username = input("Username: ")
query = "SELECT * FROM users WHERE username='" + username + "'"
```

AI may identify that directly adding user input to a SQL query can create a **SQL injection risk**.

It can suggest using a parameterized query instead.

### Example workflow

```text
Code
  ↓
AI Code Review
  ↓
Possible problems identified
  ↓
Developer reviews suggestions
  ↓
Fix code
  ↓
Test again
```

---

# 1.2 Security Reviews

AI can also be used to review code specifically from a **security perspective**.

You can ask questions such as:

```text
Review this login code for security problems.
```

or:

```text
Find possible authentication and authorization weaknesses.
```

AI may help identify areas such as:

* Weak authentication
* Missing authorization checks
* Injection risks
* Insecure session handling
* Sensitive data exposure
* Poor input validation
* Hard-coded secrets

### Important

AI may miss vulnerabilities or produce incorrect recommendations.

Therefore:

> **Never assume that code is secure just because AI says it is secure.**

---

# 1.3 Architecture Discussions

AI can help developers think about the security of an application's architecture.

For example:

```text
Frontend
    ↓
API
    ↓
Backend
    ↓
Database
```

You can ask AI:

```text
What security controls should be added to this architecture?
```

AI can help discuss:

* Authentication
* Authorization
* API security
* Database security
* Network separation
* Encryption
* Session management
* Logging and monitoring
* Rate limiting
* Secure communication

### Example

Instead of only asking:

> "How do I build a login system?"

You can ask:

> "How should I design a secure login system with authentication, session management, rate limiting, and logging?"

This encourages security to be considered during **design**, not only after coding.

---

# 1.4 Secure Coding Suggestions

AI can suggest safer ways to write code.

For example:

### Unsafe idea

```python
query = "SELECT * FROM users WHERE id=" + user_id
```

### Security concern

User-controlled input is being directly inserted into a SQL query.

### Safer approach

Use a **parameterized query** supported by the database library.

The important principle is:

```text
Untrusted input
      ↓
Safe handling
      ↓
Parameterized query
      ↓
Database
```

AI can help explain why the safer approach is recommended.

---

# 2. Validate AI Outputs

AI-generated code and security advice should **never be trusted blindly**.

The second part of AI-assisted secure development is:

> **Review → Verify → Test → Validate**

---

# 2.1 Review Security Recommendations

When AI gives a security recommendation, ask:

```text
Is this recommendation actually correct?
```

Check:

* What vulnerability is it solving?
* Why does the solution work?
* Does it introduce another problem?
* Is it appropriate for this application?
* Is it suitable for the technology being used?

### Example

AI says:

> "Disable authentication to solve the login problem."

This may technically remove the login error, but it creates a serious security problem.

Therefore:

> **A working solution is not necessarily a secure solution.**

---

# 2.2 Verify Implementation Quality

After AI generates code, the developer should inspect it.

Check:

### Input validation

```text
Is user input validated?
```

### Authentication

```text
Is the user properly authenticated?
```

### Authorization

```text
Is the user allowed to perform this action?
```

### Data protection

```text
Are passwords and sensitive data protected?
```

### Error handling

```text
Does the application expose sensitive information?
```

### Secrets

```text
Are API keys or passwords hard-coded?
```

### Dependencies

```text
Are libraries trustworthy and appropriately maintained?
```

---

# 3. AI Hallucinations

AI can sometimes generate information that **sounds correct but is actually wrong**.

For example, AI might:

* Invent a library function
* Suggest an invalid security configuration
* Recommend an outdated method
* Misunderstand a framework
* Generate vulnerable code

Therefore:

```text
AI answer
    ↓
Developer review
    ↓
Documentation check
    ↓
Testing
    ↓
Security validation
```

---

# 4. AI Does Not Replace Security Testing

AI can help identify possible problems, but security testing is still important.

Useful validation methods include:

* Code review
* Unit testing
* Integration testing
* Security testing
* Dependency scanning
* Static analysis
* Dynamic testing
* Manual review

Think of AI as **one layer of security**, not the entire security process.

---

# 5. Never Share Sensitive Information Carelessly

When using AI for code review, be careful with:

```text
Passwords
API keys
Private keys
Session tokens
Database credentials
Personal information
Confidential company data
```

### Bad

```text
Review this code:

API_KEY = "real-secret-key-here"
DB_PASSWORD = "real-password"
```

Instead, replace sensitive values:

```text
API_KEY = "<REDACTED>"
DB_PASSWORD = "<REDACTED>"
```

The principle is:

> **Remove secrets and sensitive information before sharing code with an AI system unless you are using an appropriately secured environment and are authorized to share the data.**

# 8. AI Security Checklist

Before accepting AI-generated security code, ask:

```text
☑ Do I understand what this code does?
☑ Is the recommendation actually relevant?
☑ Is the security reasoning correct?
☑ Did I verify the framework/library documentation?
☑ Does the code validate input?
☑ Does it enforce authentication?
☑ Does it enforce authorization?
☑ Does it protect sensitive data?
☑ Does it avoid hard-coded secrets?
☑ Does it handle errors safely?
☑ Did I test the implementation?
☑ Could the change introduce another vulnerability?
```

# 9. Key Difference

### AI-assisted development

```text
AI
 ↓
Helps developer
 ↓
Developer reviews
 ↓
Developer validates
 ↓
Secure implementation
```

### Blind AI usage

```text
AI
 ↓
Copy code
 ↓
Deploy immediately
```

The second approach is dangerous because AI-generated code can contain mistakes or vulnerabilities.

---

# 10. Best Practices

1. Use AI to **assist**, not replace, security expertise.
2. Ask AI to explain security risks and reasoning.
3. Review generated code before using it.
4. Verify security recommendations against trusted documentation.
5. Test AI-generated code.
6. Never blindly trust AI-generated security claims.
7. Remove secrets before sharing code.
8. Consider authentication and authorization during design.
9. Use security tools in addition to AI.
10. Keep human review as the final decision point.
