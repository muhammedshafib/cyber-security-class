# A. Defence in Depth

## What is Defence in Depth?

**Defence in Depth** is a cybersecurity strategy that uses **multiple layers of security controls** to protect systems and data.

The main idea is:

> **Don't depend on one security control. Use multiple layers.**

If one layer fails, another layer can still protect the organization.

### Example

Imagine a company server:

```text
Internet
   ↓
Firewall
   ↓
IDS/IPS
   ↓
Authentication
   ↓
Access Control
   ↓
Endpoint Security
   ↓
Application Security
   ↓
Data Encryption
   ↓
Backup
```

Even if an attacker passes the firewall, they still have to overcome other security controls.

### Layers of Defence in Depth

**1. Physical Security**

* Locks
* CCTV
* Security guards
* Access cards

**2. Network Security**

* Firewall
* IDS/IPS
* Network segmentation
* VPN

**3. Endpoint Security**

* Antivirus
* EDR
* Host firewall
* System hardening

**4. Application Security**

* Secure coding
* Input validation
* Web application firewall

**5. Identity Security**

* Strong passwords
* MFA
* Access control

**6. Data Security**

* Encryption
* Backups
* Data loss prevention

**7. Monitoring**

* SIEM
* Log monitoring
* SOC

### Advantages

* Reduces risk
* Limits attacker movement
* Provides backup security controls
* Improves detection
* Makes attacks more difficult

# B. Principle of Least Privilege

## What is Least Privilege?

The **Principle of Least Privilege (PoLP)** means:

> **Give a user, application, or system only the minimum permissions required to perform its job.**

### Example

A normal employee only needs access to their work files.

They don't need:

```text
❌ Root access
❌ Administrator privileges
❌ Access to every employee's files
```

Instead:

```text
Employee → Required files only
Admin → Administrative functions
Database service → Required database access only
```

### Why is it important?

If an employee's account is compromised, the attacker receives only the permissions available to that account.

Therefore:

**Less privilege → Smaller attack surface → Lower damage**

### Example in Linux

A normal user should not normally perform administrative operations as `root`.

Instead of giving everyone root access:

```bash
sudo usermod ...
```

administrative permissions can be granted only when necessary.

# C. Zero Trust

## What is Zero Trust?

**Zero Trust** is a security model based on the principle:

> **Never trust automatically; always verify.**

Traditional security often assumes:

```text
Inside network = Trusted
Outside network = Untrusted
```

Zero Trust does not automatically trust either.

```text
User
  ↓
Verify Identity
  ↓
Verify Device
  ↓
Check Permissions
  ↓
Allow Limited Access
  ↓
Continuously Monitor
```

### Core principles

### 1. Verify explicitly

Check:

* User identity
* Device
* Location/context
* Application
* Authentication

### 2. Least privilege

Give only the access that is necessary.

### 3. Assume breach

Always operate with the assumption that an attacker **may already be inside**.

### Example

An employee logs into a company application.

Zero Trust checks:

```text
Who are you?
      ↓
Is MFA successful?
      ↓
Is your device trusted?
      ↓
Are you allowed to access this application?
      ↓
What data are you allowed to access?
```

# D. Malware

## What is Malware?

**Malware** means **Malicious Software**.

It is software intentionally designed to:

* Damage systems
* Steal information
* Disrupt operations
* Gain unauthorized access
* Spy on users
* Encrypt files
* Perform other malicious activities

---

## Types of Malware

### 1. Virus

A **virus** attaches itself to a legitimate file or program and spreads when the infected file is executed.

Example:

```text
Clean File
   ↓
Virus attaches
   ↓
User executes file
   ↓
Virus spreads
```

---

### 2. Worm

A **worm** can spread automatically across networks without requiring a user to execute an infected file.

**Virus:** Usually requires a host file/user action.

**Worm:** Can self-propagate.

---

### 3. Trojan

A **Trojan** is malicious software disguised as legitimate software.

Example:

> A fake software installer appears legitimate but secretly performs malicious actions.

---

### 4. Ransomware

Ransomware typically prevents access to files or systems, often by encrypting data, and demands payment.

```text
Malware
   ↓
Files affected
   ↓
Data becomes inaccessible
   ↓
Attacker demands ransom
```

Good security practice includes maintaining **offline or otherwise protected backups**.

---

### 5. Spyware

Spyware secretly monitors activity and may collect information such as:

* Browsing activity
* Credentials
* Personal information

---

### 6. Keylogger

A keylogger records keystrokes.

It can potentially capture:

* Usernames
* Passwords
* Messages
* Other typed information

---

### 7. Adware

Adware displays unwanted advertisements.

Some adware is merely annoying, while malicious variants can also track users or redirect traffic.

---

### 8. Rootkit

A rootkit is designed to **hide malicious activity or maintain privileged access** to a system.

It can be difficult to detect.

---

### 9. Bot/Botnet Malware

A compromised device may become part of a **botnet**, a collection of infected devices controlled by an attacker.

Botnets can be used for activities such as:

* DDoS attacks
* Spam
* Malware distribution

---

# E. Common Attack Techniques

Attack techniques are methods attackers use to compromise systems, users, networks, or applications.

Common examples:

* Phishing
* Social engineering
* Credential attacks
* Malware
* Exploitation of vulnerabilities
* Password attacks
* Web application attacks
* Denial-of-service attacks
* Supply-chain attacks
* Insider attacks

---

# Types of Phishing Attacks

## 1. Email Phishing

Fake emails are sent to victims.

Example:

> "Your account will be suspended. Click here to verify."

The goal may be to steal credentials or deliver malware.

---

## 2. Spear Phishing

A targeted phishing attack aimed at a **specific person or organization**.

Example:

An attacker creates a convincing message specifically targeting an employee in the finance department.

---

## 3. Whaling

A phishing attack targeting a **high-value individual**, such as:

* CEO
* CFO
* Director
* Senior executive

---

## 4. Smishing

**SMS + Phishing = Smishing**

Phishing through text messages.

Example:

> "Your package could not be delivered. Verify your information."

---

## 5. Vishing

**Voice + Phishing = Vishing**

Phishing through phone calls or voice communication.

Example:

Someone pretends to be a bank employee and asks for sensitive information.

---

## 6. Clone Phishing

An attacker creates a copy of a legitimate email or message and modifies it to contain a malicious link or attachment.

---

## 7. Pharming

Pharming redirects users to a fraudulent website even when they believe they are visiting the legitimate site.

---

# F. Credential Attacks

## What are Credential Attacks?

Credential attacks attempt to obtain or abuse authentication information such as:

* Usernames
* Passwords
* Session tokens
* API keys
* Authentication credentials

### Common types

### 1. Brute Force

The attacker tries many possible password combinations.

Conceptually:

```text
Password 1 → Fail
Password 2 → Fail
Password 3 → Fail
...
Correct password → Success
```

Strong passwords and account lockout/rate limiting help defend against this.

---

### 2. Dictionary Attack

Instead of trying every possible combination, attackers use a list of commonly used words/passwords.

---

### 3. Password Spraying

The attacker tries **one common password against many accounts**, rather than many passwords against one account.

This can help attackers avoid some account-lockout controls.

---

### 4. Credential Stuffing

Attackers use previously leaked username/password combinations against other services.

Why does it work?

Because some people reuse passwords.

### Defense

**Use unique passwords for every service.**

---

### 5. Phishing for Credentials

Victims are tricked into entering their credentials into a fake login page.

---

### 6. Keylogging

Malware records keystrokes to potentially capture credentials.

---

## Credential Attack Defense

* Strong unique passwords
* Password manager
* MFA
* Account lockout/rate limiting
* Monitor leaked credentials
* User awareness training
* Avoid password reuse
* Use phishing-resistant authentication where available

# G. Reconnaissance

## What is Reconnaissance?

**Reconnaissance (Recon)** is the process of **collecting information about a target before an attack or security assessment**.

In authorized penetration testing, recon helps security professionals understand the target's attack surface.

```text
Reconnaissance
      ↓
Information Gathering
      ↓
Identify Attack Surface
      ↓
Security Testing
```

There are two major types.

---

# 1. Passive Reconnaissance

Passive reconnaissance collects information **without directly interacting with the target systems in a noticeable way**.

Examples:

* Search engines
* Public websites
* Public documents
* News articles
* Public DNS information
* Public social media information
* WHOIS/RDAP information where available
* Public breach disclosures

### Example

A security tester researches a company's publicly available website and documentation to understand its technology stack.

**No direct probing of the target is required.**

---

# 2. Active Reconnaissance

Active reconnaissance involves **direct interaction with the target environment**.

Examples:

* Port scanning
* Service enumeration
* Network probing
* Banner identification

Because active recon generates traffic to the target, it is more likely to be detected.

### Difference

| Passive                        | Active                            |
| ------------------------------ | --------------------------------- |
| Indirect information gathering | Direct interaction                |
| Lower chance of detection      | Higher chance of detection        |
| Public sources                 | Target systems                    |
| Example: Search engines        | Example: Authorized port scanning |

**Important:** Active reconnaissance should only be performed against systems you own or have explicit permission to test.

# H. Web and Internet Security

The internet can be thought of as containing different layers of visibility.

## 1. Surface Web

The **Surface Web** is the part of the internet that is generally indexed by standard search engines.

Examples:

* News websites
* Public blogs
* Company websites
* Public documentation
* Wikipedia

```text
Internet
   ↓
Surface Web
   ↓
Search engines can commonly index it
```

---

# 2. Deep Web

The **Deep Web** refers to content that is **not indexed by normal search engines**.

This does **not** mean it is illegal.

Examples:

* Online banking portals
* Private email
* Company intranets
* Subscription databases
* Cloud dashboards
* Medical portals

You can access these using authentication or a direct/private link.

### Important

**Deep Web ≠ Dark Web**

---

# 3. Dark Web

The **Dark Web** is a portion of the internet that is intentionally hidden and typically requires specialized software/networks to access.

It can be used for both:

* Legitimate privacy-focused purposes
* Criminal activities

Therefore, the Dark Web itself should not simply be described as "illegal internet."

### Comparison

| Surface Web                      | Deep Web                                      | Dark Web                    |
| -------------------------------- | --------------------------------------------- | --------------------------- |
| Publicly accessible              | Usually requires authentication/direct access | Intentionally hidden        |
| Commonly indexed                 | Usually not indexed                           | Not normally indexed        |
| Google/Bing can index much of it | Search engines generally don't index it       | Requires specialized access |
| News websites                    | Banking portal                                | Hidden services             |

# I. DoS and DDoS

## DoS — Denial of Service

A **Denial-of-Service (DoS)** attack attempts to make a service, system, or network **unavailable to legitimate users**.

Simple example:

```text
Many requests
      ↓
Server resources exhausted
      ↓
Legitimate users
      ↓
Cannot access service
```

---

# DDoS — Distributed Denial of Service

A **Distributed Denial-of-Service (DDoS)** attack performs the same general objective using **many distributed systems/devices**.

```text
Device A ─┐
Device B ─┤
Device C ─┼──→ Target Server
Device D ─┤
Device E ─┘
```

The distributed nature makes mitigation more difficult.

---

## DoS vs DDoS

| DoS                                     | DDoS                                |
| --------------------------------------- | ----------------------------------- |
| Usually originates from one/few sources | Comes from many distributed sources |
| Easier to identify in some cases        | More difficult to filter            |
| Smaller scale is common                 | Can reach very large scale          |
| Single-source attack                    | Distributed attack                  |

---

## Types of DoS/DDoS

### 1. Volumetric Attacks

Attempt to consume network bandwidth with large amounts of traffic.

### 2. Protocol Attacks

Target weaknesses in network/protocol handling and network infrastructure resources.

### 3. Application-Layer Attacks

Target application resources.

Example:

A web application receives a large number of expensive requests, exhausting server resources.

---

# J. External Threats

External threats originate **outside the organization's trusted environment**.

Examples:

### 1. Cybercriminals

Attack systems for financial gain.

### 2. Hacktivists

Conduct attacks based on ideological or political motivations.

### 3. Nation-State Actors

Government-backed or government-associated groups may conduct cyber operations for intelligence or strategic objectives.

### 4. Script Kiddies

Less-skilled attackers who use existing tools and techniques without necessarily understanding them deeply.

### 5. External Contractors/Third Parties

A compromised vendor or third-party service can become an entry point into an organization.
