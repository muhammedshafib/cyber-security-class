# Module 3 — OSI Model

## Complete Important Notes: Functions, Protocols, Attacks & What Happens at Each Layer

The **OSI (Open Systems Interconnection) Model** is a **7-layer conceptual model** used to understand how computers communicate over a network.

It is very important for **networking, cybersecurity, troubleshooting, and penetration testing**.

### OSI Layers — Easy Memory Trick

From **Layer 7 → Layer 1**:

> **A P S T N D P**
> **All People Seem To Need Data Processing**

| Layer | Name         | Main Function                        |
| ----- | ------------ | ------------------------------------ |
| **7** | Application  | Network services for applications    |
| **6** | Presentation | Data format, encryption, compression |
| **5** | Session      | Establish/manage/end sessions        |
| **4** | Transport    | End-to-end delivery                  |
| **3** | Network      | IP addressing & routing              |
| **2** | Data Link    | Frames, MAC addresses, switching     |
| **1** | Physical     | Bits, cables, radio signals          |

---

# 1. Application Layer — Layer 7

### What happens here?

The **Application Layer** is the layer closest to the user. It provides network services that applications use to communicate.

It does **not mean the actual application itself**; rather, it provides networking functions used by applications.

### Functions

* Network resource access
* Web communication
* Email services
* File transfer
* Name resolution
* Remote access
* Application-level communication

### Important protocols

| Protocol   | Purpose                                 |
| ---------- | --------------------------------------- |
| **HTTP**   | Web communication                       |
| **HTTPS**  | Secure web communication                |
| **DNS**    | Domain-name resolution                  |
| **FTP**    | File transfer                           |
| **SMTP**   | Sending email                           |
| **POP3**   | Receiving email                         |
| **IMAP**   | Email access/synchronization            |
| **SSH**    | Secure remote administration            |
| **Telnet** | Remote access without modern encryption |
| **DHCP**   | Automatic IP configuration              |
| **SNMP**   | Network/device management               |

### Example

When you type:

```text
https://example.com
```

your browser uses application-layer protocols such as **HTTP/HTTPS**.

### Common attacks

* Phishing
* SQL Injection
* Cross-Site Scripting (XSS)
* Command injection
* Application-layer DoS
* Broken authentication
* Directory traversal
* API attacks

### Security controls

* Web Application Firewall (WAF)
* Input validation
* Secure coding
* Authentication
* Authorization
* HTTPS
* Security testing
* API security

---

# 2. Presentation Layer — Layer 6

### What happens here?

The Presentation Layer deals with **how data is represented** so that different systems can understand it.

### Main functions

### 1. Data Translation

Converts data between different formats/representations.

### 2. Encryption/Decryption

Helps provide data confidentiality.

### 3. Compression/Decompression

Reduces the size of transmitted data.

### Examples of data formats/technologies

* JSON
* XML
* JPEG
* PNG
* ASCII
* Unicode
* UTF-8

Security-related technologies can include:

* TLS-related data protection
* Encryption formats

> In real-world TCP/IP networking, OSI Layers 5–7 don't always map cleanly to separate protocols. They are primarily useful as a conceptual model.

### Attacks/security issues

* Weak encryption
* Downgrade attacks
* Certificate/TLS-related attacks
* Data manipulation
* Encoding-related vulnerabilities

### Security

* Strong encryption
* Proper certificate validation
* Secure TLS configuration
* Avoid deprecated cryptographic algorithms

---

# 3. Session Layer — Layer 5

### What happens here?

The Session Layer manages **communication sessions** between applications.

A session is basically an ongoing communication relationship.

### Functions

* Establish sessions
* Maintain sessions
* Synchronize communication
* Terminate sessions
* Session recovery/checkpoints

### Example

Imagine:

```text
Client ───────── Server
       Session
```

The session layer conceptually manages the communication relationship.

### Security issues/attacks

* Session hijacking
* Session fixation
* Session replay
* Session theft
* Unauthorized session reuse

### Example

If an attacker obtains a valid user's session token, they may attempt to use that session to impersonate the user.

### Security

* Secure session tokens
* HTTPS
* Session expiration
* Token rotation
* Secure cookie settings
* Re-authentication for sensitive actions

---

# 4. Transport Layer — Layer 4

### What happens here?

The Transport Layer provides **end-to-end communication between hosts/processes**.

It is one of the most important layers for cybersecurity.

### Main protocols

## TCP

**Transmission Control Protocol**

TCP provides reliable, connection-oriented communication.

It uses:

* Sequence numbers
* Acknowledgements
* Retransmission
* Flow control

### TCP connection

A TCP connection normally starts with a **three-way handshake**:

```text
Client                  Server
  │                       │
  │──── SYN ─────────────→│
  │←─── SYN-ACK ──────────│
  │──── ACK ─────────────→│
  │                       │
  │   Connection Ready    │
```

## UDP

**User Datagram Protocol**

UDP is connectionless and has lower overhead than TCP.

It does not provide TCP-style reliability.

Used by applications such as:

* DNS
* DHCP
* Streaming
* VoIP
* Online games

### Ports

Transport Layer uses **port numbers** to identify services/processes.

Examples:

|  Port | Common Service |
| ----: | -------------- |
| 20/21 | FTP            |
|    22 | SSH            |
|    23 | Telnet         |
|    25 | SMTP           |
|    53 | DNS            |
|    80 | HTTP           |
|   443 | HTTPS          |
|   110 | POP3           |
|   143 | IMAP           |
|  3389 | RDP            |

### Attacks

* SYN flood
* UDP flood
* Port scanning
* TCP reset attacks
* Connection exhaustion

### Security

* Firewall
* Network segmentation
* Rate limiting
* IDS/IPS
* Disable unnecessary services/ports

---

# 5. Network Layer — Layer 3

### What happens here?

The Network Layer handles:

* **Logical addressing**
* **Routing**
* **Packet forwarding**

The most important protocol is **IP**.

### Important protocols

* IPv4
* IPv6
* ICMP
* IPsec
* Routing protocols such as OSPF and BGP

### IP Address

Example:

```text
192.168.1.10
```

The IP address identifies a network interface logically.

### Router

Routers primarily operate at Layer 3.

```text
Network A
   ↓
Router
   ↓
Network B
```

The router determines where packets should go.

### Attacks

* IP spoofing
* ICMP-based attacks
* Route manipulation
* Routing attacks
* Fragmentation-related attacks
* Network-layer DoS/DDoS

### Security

* Access control lists
* Firewalls
* Routing security
* Anti-spoofing filters
* Network segmentation
* IDS/IPS

---

# 6. Data Link Layer — Layer 2

### What happens here?

The Data Link Layer handles communication between devices on the **same local network/link**.

Important concepts:

* Frames
* MAC addresses
* Ethernet
* Switching
* VLANs
* Error detection

### MAC Address

A MAC address identifies a network interface at the local-link level.

Example:

```text
00:1A:2B:3C:4D:5E
```

### Important technologies/protocols

* Ethernet (802.3)
* Wi-Fi (802.11)
* ARP
* VLAN (802.1Q)
* STP

### Switch

A network switch primarily operates at Layer 2.

```text
PC1 ─┐
PC2 ─┼── Switch ── Server
PC3 ─┘
```

### Attacks

#### 1. ARP Spoofing/Poisoning

An attacker sends false ARP information to associate their MAC address with another device's IP address.

Possible consequences:

* Traffic interception
* Man-in-the-middle attacks
* Traffic disruption

#### 2. MAC Flooding

An attacker attempts to overwhelm a switch's MAC address table.

#### 3. VLAN-related attacks

Misconfigurations can potentially allow unauthorized traffic between VLANs.

#### 4. Rogue DHCP

An unauthorized DHCP server provides incorrect network configuration to clients.

### Security

* Port security
* DHCP snooping
* Dynamic ARP Inspection
* VLAN segmentation
* 802.1X
* Secure switch configuration

# 7. Physical Layer — Layer 1

### What happens here?

The Physical Layer transmits **raw bits** across a physical medium.

```text
101010101010
```

It deals with:

* Electrical signals
* Radio signals
* Light signals
* Cables
* Connectors
* Physical transmission

### Examples

* Ethernet cables
* Fiber-optic cables
* Wi-Fi radio
* Hubs
* Repeaters
* Network connectors

### Attacks

Physical attacks can include:

* Cable cutting
* Device theft
* Hardware tampering
* Unauthorized physical access
* Signal interference/jamming
* Eavesdropping on poorly protected physical links

### Security

* Physical access control
* CCTV
* Locked network rooms
* Secure cable management
* Tamper protection
* Redundant connections

# How Data Travels Through the OSI Model

Suppose you open:

```text
https://example.com
```

The data moves down the layers on the sender side:

```text
Application       → HTTP/HTTPS data
       ↓
Presentation      → Data representation/encryption concepts
       ↓
Session           → Session management
       ↓
Transport         → TCP segment
       ↓
Network            → IP packet
       ↓
Data Link          → Ethernet/Wi-Fi frame
       ↓
Physical           → Bits/signals
```

At the receiving system, the process is reversed:

```text
Physical
   ↓
Data Link
   ↓
Network
   ↓
Transport
   ↓
Session
   ↓
Presentation
   ↓
Application
```

This process is called **encapsulation and decapsulation**.

---

# Encapsulation

As data moves **down** the sender's OSI stack, each layer adds information.

```text
Application
   ↓
Data
   ↓
Transport
   ↓
Segment
   ↓
Network
   ↓
Packet
   ↓
Data Link
   ↓
Frame
   ↓
Physical
   ↓
Bits
```

### Easy memory

> **Data → Segment → Packet → Frame → Bits**

---

# Decapsulation

At the receiving computer, headers are removed as data moves upward.

```text
Bits
 ↓
Frame
 ↓
Packet
 ↓
Segment
 ↓
Data
```

# External Topics You Should Know

For a **complete Module 4**, these supporting concepts are also important.

## 1. TCP/IP Model

The real internet is generally described using the **TCP/IP model**, rather than strictly using all seven OSI layers.

A common four-layer representation:

| TCP/IP              | Rough OSI Equivalent |
| ------------------- | -------------------- |
| Application         | OSI 5–7              |
| Transport           | OSI 4                |
| Internet            | OSI 3                |
| Network Access/Link | OSI 1–2              |

### OSI vs TCP/IP

**OSI:** 7-layer conceptual/reference model.

**TCP/IP:** Practical protocol architecture used by the Internet.

# 2. MAC Address vs IP Address vs Port

This is extremely important.

### MAC Address

Identifies a network interface on the local network.

**Layer 2**

### IP Address

Identifies a host/interface logically for network communication.

**Layer 3**

### Port

Identifies a service/process endpoint.

**Layer 4**

Example:

```text
MAC → Which network interface?
IP  → Which host/network?
Port → Which service?
```

# 4. Common Troubleshooting by OSI Layer

This is very useful in real cybersecurity and networking.

### Layer 1 problem

**Symptom:** No physical connection.

Check:

* Cable
* Power
* Wi-Fi signal
* Network interface

### Layer 2 problem

**Symptom:** Local network communication fails.

Check:

* MAC address
* VLAN
* Switch
* ARP
* Port configuration

### Layer 3 problem

**Symptom:** Cannot reach another network.

Check:

* IP address
* Subnet mask/prefix
* Default gateway
* Routing

### Layer 4 problem

**Symptom:** Host is reachable, but a service doesn't respond.

Check:

* TCP/UDP
* Ports
* Firewall
* Listening services

### Layer 7 problem

**Symptom:** Network works, but the application doesn't.

Check:

* DNS
* HTTP/HTTPS
* Application configuration
* Authentication
* Application logs

# 5. OSI Model and Cybersecurity

Security professionals use the OSI model to determine **where an attack or problem is occurring**.

For example:

```text
Physical      → Physical tampering
      ↓
Data Link     → ARP spoofing
      ↓
Network       → IP/routing attacks
      ↓
Transport     → SYN flood
      ↓
Session       → Session hijacking
      ↓
Presentation  → Encryption/TLS issues
      ↓
Application   → SQL injection/XSS
```

This helps a security analyst answer:

> **"At which layer is this attack happening?"**
