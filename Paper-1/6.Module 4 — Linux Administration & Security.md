# 1. Linux File System

Linux organizes everything in a hierarchical filesystem.

The top level is:

```bash
/
```

This is called the **root directory**.

Common directories:

| Directory | Purpose                        |
| --------- | ------------------------------ |
| `/`       | Root of filesystem             |
| `/home`   | Normal users' home directories |
| `/root`   | Root user's home directory     |
| `/etc`    | Configuration files            |
| `/var`    | Variable data and logs         |
| `/tmp`    | Temporary files                |
| `/usr`    | Programs and libraries         |
| `/bin`    | Essential commands             |
| `/sbin`   | System administration commands |
| `/dev`    | Device files                   |
| `/proc`   | Process/kernel information     |
| `/opt`    | Optional software              |

# 2. List Files

The main command is:

```bash
ls
```

Example:

```bash
ls
```

Shows files and directories in the current directory.

### Long listing

```bash

```

Example:

```text

```

This gives information such as:

* File type
* Permissions
* Owner
* Group
* File size
* Date/time
* Filename

### List with details and hidden files

```bash
ls -la
```

### Human-readable file sizes

```bash
ls -lh
```

### Useful combinations

```bash
ls -lah
```

# 3. Hidden Files

In Linux, a filename beginning with `.` is normally treated as a **hidden file**.

Example:

```text
.config
.bashrc
.profile
```

Normal:

```bash
ls
```

Hidden files aren't normally displayed.

To see them:

```bash
ls -a
```

or:

```bash
ls -la
```

### Important

`-a` means **all**, including hidden entries.

# 4. File Permissions

Linux uses permissions to control who can:

* Read
* Write
* Execute

A permission example:

```text
-rwxr-xr--
```

Break it down:

```text
- rwx r-x r--
│ │   │   │
│ │   │   └── Others
│ │   └────── Group
│ └────────── Owner
└──────────── File type
```

---

# 5. Permission Types

| Symbol | Permission    | Meaning                        |
| ------ | ------------- | ------------------------------ |
| `r`    | Read          | View/read data                 |
| `w`    | Write         | Modify data                    |
| `x`    | Execute       | Execute file / enter directory |
| `-`    | No permission | Permission not granted         |

---

# 6. User Categories

Linux permissions normally apply to three categories:

### 1. User/Owner — `u`

The owner of the file.

### 2. Group — `g`

Users belonging to the file's group.

### 3. Others — `o`

Everyone else.

So:

```text
u = user/owner
g = group
o = others
```

---

# 7. Understanding Permission Example

Consider:

```text
-rwxr-xr--
```

Break it into:

```text
rwx | r-x | r--
 ↑     ↑     ↑
User  Group Others
```

### Owner

```text
rwx
```

Can:

* Read
* Write
* Execute

### Group

```text
r-x
```

Can:

* Read
* Execute

Cannot:

* Write

### Others

```text
r--
```

Can:

* Read

Cannot:

* Write
* Execute

# 8. chmod — Change Permissions

`chmod` means:

> **Change Mode**

It changes file or directory permissions.

Example:

```bash
chmod u+x script.sh
```

Adds execute permission to the owner.

---

## Symbolic chmod

### Add permission

```bash
chmod u+x file.txt
```

Owner gets execute permission.

### Remove permission

```bash
chmod u-x file.txt
```

Owner loses execute permission.

### Add group write permission

```bash
chmod g+w file.txt
```

### Remove others' write permission

```bash
chmod o-w file.txt
```

### Multiple permissions

```bash
chmod u+rwx,g+rx,o+r file.txt
```

---

# 9. Numeric chmod

Linux permissions can also be represented using numbers.

| Permission | Number |
| ---------- | -----: |
| `---`      |      0 |
| `--x`      |      1 |
| `-w-`      |      2 |
| `-wx`      |      3 |
| `r--`      |      4 |
| `r-x`      |      5 |
| `rw-`      |      6 |
| `rwx`      |      7 |

### Example

```bash
chmod 755 script.sh
```

Means:

```text
Owner  → 7 → rwx
Group  → 5 → r-x
Others → 5 → r-x
```

So:

```text
rwxr-xr-x
```

Another common example:

```bash
chmod 644 file.txt
```

Means:

```text
Owner  → rw-
Group  → r--
Others → r--
```

Result:

```text
rw-r--r--
```

# 10. Changing File Owner

The command is:

```bash
chown
```

Example:

```bash
sudo chown shafi file.txt
```

Changes the owner to `shafi`.

Check:

```bash
ls -l file.txt
```

---

# 11. Changing Owner and Group

You can change both at the same time:

```bash
sudo chown shafi:developers file.txt
```

Meaning:

```text
Owner → shafi
Group → developers
```

---

# 12. Changing Only Group

Use:

```bash
chgrp
```

Example:

```bash
sudo chgrp developers file.txt
```

Now the group becomes `developers`.

---

# 13. Recursive Ownership/Permission Changes

For directories, `-R` means **recursive**.

Example:

```bash
sudo chown -R shafi:developers project/
```

This changes ownership for the directory and its contents.

### Security warning

Be careful with recursive commands.

Incorrect recursive ownership or permission changes can break system security or applications.

Avoid blindly doing things such as:

```bash
chmod -R 777 /
```

This is extremely dangerous.

# 18. User Permissions and sudo

Linux has a highly privileged account called:

```text
root
```

The root user can perform almost all administrative operations.

Instead of logging in as root all the time, administrators commonly use:

```bash
sudo command
```

Example:

```bash
sudo apt update
```

### Why `sudo`?

It allows authorized users to execute specific administrative commands with elevated privileges.

This follows the **Principle of Least Privilege**.

# 19. Groups

A **group** is a collection of users.

Groups make permission management easier.

Example:

```text
developers
   ├── user1
   ├── user2
   └── user3
```

Instead of assigning permissions individually, you can assign permissions to the group.

---

# 20. Create a Group

```bash

```

Check groups:

```bash

```

Search for a specific group:

```bash

```


* `-a` → append
* `-G` → supplementary group



# 24. grep Command

`grep` is one of the most important Linux commands.

It searches for **text patterns**.

Basic syntax:

```bash
grep "pattern" file
```

Example:

```bash
grep "error" log.txt
```

It searches `log.txt` for lines containing `error`.

---

## Useful grep options

### Case-insensitive

```bash
grep -i "error" log.txt
```

### Show line numbers

```bash
grep -n "error" log.txt
```

### Invert search

```bash
grep -v "error" log.txt
```

Shows lines that do **not** contain `error`.

### Recursive search

```bash
grep -r "password" directory/
```

Searches files inside a directory recursively.

### Count matches

```bash
grep -c "error" log.txt
```

# 25. Pipe `|`

The pipe is extremely important in Linux.

It sends the **output of one command as input to another command**.

Basic structure:

```bash
command1 | command2
```

Example:

```bash
ps aux | grep firefox
```

Here:

```text
ps aux
  ↓
lists processes
  ↓
grep firefox
  ↓
finds Firefox-related lines
```

Another example:

```bash
ls -la | grep ".conf"
```

This displays entries matching `.conf`.

---

### `>` — overwrite/create

### `>>` — append

# 30. Kill a Process

The command is:

```bash
kill PID
```

Example:

```bash
kill 1234
```

This normally sends **SIGTERM**, asking the process to terminate gracefully.

### Force termination

```bash
kill -9 1234
```

`SIGKILL` immediately terminates the process and does not allow it to clean up normally.

### Important

Prefer normal termination first:

```bash
kill PID
```

Use:

```bash
kill -9 PID
```

only when necessary.

---

# 31. `pkill`

You can terminate processes by name:

```bash
pkill firefox
```

Use caution because it can affect multiple matching processes.

# 36. File Permissions — Security Example

Suppose:

```text
-rw------- 1 shafi shafi password.txt
```

This means:

```text
Owner  → rw-
Group  → ---
Others → ---
```

Only the owner can read/write the file.

This is much safer than:

```text
-rw-rw-rw-
```

where everyone can modify it.

---

# 37. `chmod 777` — Why It Is Dangerous

You may see:

```bash
chmod 777 file
```

This means:

```text
Owner  → rwx
Group  → rwx
Others → rwx
```

Everyone can read, write, and execute it.

This can create serious security problems.

### Better approach

Give only the permissions actually required.

For example:

```bash
chmod 640 sensitive.txt
```

means:

```text
Owner → rw-
Group → r--
Others → ---
```

---

# 38. Linux Permission Numeric System

Remember:

```text
r = 4
w = 2
x = 1
```

Add them:

```text
rwx = 4 + 2 + 1 = 7
rw- = 4 + 2 = 6
r-x = 4 + 1 = 5
r-- = 4
-w- = 2
--x = 1
--- = 0
```

Therefore:

```bash
chmod 755 file
```

means:

```text
7 → rwx
5 → r-x
5 → r-x
```

# 44. Important Linux Security Concepts

### Authentication

Determines:

> **Who are you?**

Examples:

* Password
* SSH key
* MFA

### Authorization

Determines:

> **What are you allowed to do?**

Examples:

* File permissions
* Groups
* sudo

### Accounting/Auditing

Determines:

> **What did you do?**

Examples:

* Logs
* Audit records
* Command history

Together:

```text
Authentication
      ↓
Authorization
      ↓
Auditing
```
